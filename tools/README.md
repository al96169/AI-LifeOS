# tools（动作与脚本）

这一层是助理的手脚：把感知取回来，把动作真正做出来。所有判断都在 `DNA/` 与 personality 实例的 Markdown 里，这里不含任何判断。

## 组成

| 目录 | 职责 | 不做什么 |
|---|---|---|
| `actions/` | 写闹钟、发 IM、临界通知、云语音外呼、代下单 | 不判断该不该执行 |
| `channels/` | IM 渠道适配（base / 企微 / QQ / 飞书） | 不含决策逻辑 |
| `sensors/` | 感知采集：天气、ETA、日历、电量、前台进程，带缓存与新鲜度标注 | 不做融合判断，融合交给定义文件的规则 |
| `lib/` | 配置与密钥读取、缓存、日志、执行结果封装 | 不含业务判断 |
| `scripts/` | 一次性与运维脚本 | 用完可删，不承载常驻逻辑 |

函数签名见 `../DNA/架构与目录.md` 的接口契约。

## 执行结果契约

每个动作函数返回：

```
{ok: bool, action: str, detail: {...}, error: str|null, executed_at: ts}
```

失败不得静默吞掉，必须回传，由助理决定是否降级、是否记录。

## 配置与密钥

- 运行时参数读实例的 `config.md`
- 密钥读实例的 `long-term/secrets.env`，代码中只引用变量名，不出现明文
- 缺失任一必需配置时，服务启动即报出明确缺失项，不静默降级

## 启动与常驻

- 形态：随电脑开机自启的常驻进程
- 主循环：低频轮询调度加事件监听，触发信号由 `../brain/triggers/` 产生
- 电脑关机或休眠期间，关键提醒由手机侧本地兜底，恢复后补收状态

## 代码规模预期

核心逻辑加起来应当很小。如果发现某个「策略」正在被写成代码分支，说明它本该是一份场景定义，把它挪回实例的 `skills/`。

## 与环境的关系

本目录全部内容都是当前环境下的实现，可以随时被重写、换语言重做、或整体丢弃。`DNA/` 与 personality 实例则要能搬到任何地方继续成立，两者之间只靠上面那组接口语义连接。

因此换模型、换 IM 渠道、换外呼供应商、换平台，代价应当止于重写本目录里的适配部分，不涉及任何判断。约束条文见 `../DNA/铁律.md`。
