# tools（动作与脚本）

助理的手脚：把感知取回来、把动作做出来。所有判断都在 `DNA/` 与实例的 Markdown 里，这里不含任何判断。

| 目录 | 职责 |
|---|---|
| `actions/` | 写闹钟、发 IM、临界通知、云外呼、代下单 |
| `channels/` | IM 渠道适配（base / 企微 / QQ / 飞书） |
| `sensors/` | 感知采集：天气、ETA、日历、电量、前台进程，带缓存与新鲜度 |
| `lib/` | 配置与密钥读取、缓存、日志、结果封装 |
| `scripts/` | 一次性与运维脚本，用完可删 |

函数签名见 `../../DNA/架构与目录.md` 接口契约。

## 动作注册表

每个动作登记名称、参数 Schema、返回结构。模型看到的工具清单 = 注册表 ∩ `capabilities.md` 可用者，能力未达可用不暴露。

## 授权两层

软判断在模型（读 `rules/授权边界.md` 自觉）；硬上限在工具层（节流次数、单笔额度读 `config.md` 计数拦截）。两层都要——软判断管得体，硬上限兜底，提示词注入骗不过计数。

## 对外命令行入口

除被引擎直接调用外，每个动作与感知都要有命令行入口供宿主通过命令执行调用：`tools <动作名> --json [参数]`，返回结构化结果。这是宿主与工具之间唯一通路——宿主不直接改文件、不直接发请求，动作一律走入口，幂等与授权上限才有地方落。

## 执行结果

每个动作返回 `{ok, action, detail, error, executed_at}`。失败不得静默吞掉，由助理决定降级。

## 配置与密钥

参数读实例 `config.md`，密钥读 `secrets.env`（代码只引变量名）；缺必需配置服务启动即报缺失项，不静默降级。

## 边界

全部内容都是当前环境实现，可随时重写、换语言、整体丢弃。`DNA/` 与实例要能搬到任何地方继续成立，两者只靠接口语义连接——换模型、换渠道、换供应商，代价止于重写本目录适配。若发现某「策略」正在被写成代码分支，它本该是份场景定义，挪回实例 `skills/`。条文见 `DNA/铁律.md`。
