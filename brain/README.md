# brain（运行时引擎）

引擎把定义读进来，按决策循环推进，再把动作交给工具层。它不含任何判断，也不含任何用户信息。

## 组成

| 目录 | 职责 | 不做什么 |
|---|---|---|
| `runtime/` | 主循环、会话装配、状态加载与写回、开机自启 | 不含业务判断 |
| `models/` | 模型接入与提示装配 | 不解析业务语义 |
| `triggers/` | 定时触发与事件触发 | 不决定「要不要打扰」 |
| `router/` | 登记各宿主的反调方式，唤醒其中一个 | 不判断该不该打扰 |

## 装配一次决策

1. 按 user_id 找到 personality 实例
2. 读 `DNA/` 的规范与 `DNA/决策循环.md`
3. 读实例的 `assistant.md`、`rules/`、命中的 `skills/`、`short-term/context.md`、`long-term/capabilities.md`
4. 把上述内容拼成提示，交给 `models/`
5. 拿到工具调用后，转给 `tools/` 执行
6. 结果按 `DNA/记忆规范.md` 写回实例的记忆

## 边界

引擎可以在任何时刻被重写、被换语言重做。判断某段逻辑该不该留在这里，用这个问题：把它删掉，助理还是不是一个完整的、可理解的人。是，则它属于引擎；不是，则它必须回到 `DNA/` 或 personality 实例。

更快的自检：这段代码里有没有出现场景的名字、场景的阈值、或者「选 A 还是选 B」这类取舍？有就是错的，无论它写得多可配置。

约束条文见 `../DNA/铁律.md`。

## 状态

`runtime/state/` 存放进程级状态，含 DNA 目录指纹。它不入库。
