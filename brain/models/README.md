# models

模型接入、上下文装配与工具编排（自建推理段时用；交给宿主则宿主代劳）。

## 装配分两层

**常驻前缀**：`assistant.md`、`rules/` 全部、`capabilities.md`——跨待办不变，可被提示缓存命中，须字节稳定（不塞时间戳或当次情境）。**按次注入**：命中的 `skills/`、待办情境快照、`context.md`、`long-term/memory/` 相似度最高少量条目、`决策循环.md`。顺序按 `架构与目录.md` 加载顺序。

## 工具清单从能力状态派生

暴露给模型 = `tools/` 注册全部动作 ∩ `capabilities.md` 中「可用」者。第二步不能省：未申请能力出现在清单里，模型会调它然后收一个必败调用。

## 多轮工具调用

一次请求后模型可能返回 `tool_calls`，按序补齐：每条 `tool_calls` 都要有一条带 `tool_call_id` 的 `tool` 消息回执，否则协议不完整。工具结果原样回传（含失败），失败由模型决定降级，模型层不兜。

## 终止

三个刹车：工具调用轮数上限（建议 8）、单待办总时长上限、连续两次相同调用即中断。触顶不算成功，见 `决策循环.md`。

## 调用参数

端点/型号/温度/超时/重试取自实例 `config.md`，温度建议 0.2。换模型只改这一处，定义与工具层不动。

## 上下文预算

不塞整个实例，只放命中场景与必要规则。触发器已采集过一轮感知（写在待办情境快照），模型先看快照、不够再调工具补，省一次往返。
