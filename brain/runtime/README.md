# runtime

常驻服务的入口、主循环与守护进程。

## 职责

- **单实例守门**：启动时取机器锁，再逐个为 user_id 取人格锁。规则见 `../../DNA/守护进程.md`，两级锁与退让逻辑是硬要求，不能省
- **常驻与自愈**：随电脑开机自启，主循环打点，卡死由内部看门狗触发退出、外部服务管理器重新拉起
- **会话装配**：按 user_id 装载 personality 实例，一个进程可同时持有多个用户的会话，状态不交叉
- **推进决策**：依据 `../triggers/` 的触发信号启动一次决策，按 `../../DNA/决策循环.md` 的步骤走
- **记忆读写**：按 `../../DNA/记忆规范.md` 读写实例的 `long-term/` 与 `short-term/`
- **只读校验**：以只读方式加载 `../../DNA/`，计算目录指纹并与 `state/` 里上次的值比对，不一致时向用户报告

## 处理一条待办的完整链路

```
触发器写入待办
 → 取件：移到 claimed/，写入领取者与领取时刻
 → 装配：models/ 拼上下文与工具清单
 → 调用：一次 chat(messages, tools)
 → 若有 tool_calls：交 tools/ 执行，结果按 tool 消息回灌，再调一次
 → 收敛：模型不再要工具，得到结论与文案
 → 收尾：需要对外动作的由 tools/ 执行完
 → 写回：结论写 done/，情景记忆追加，short-term/context.md 更新
```

两条硬要求。

幂等：同一待办 id 重复处理不得重复执行对外动作。执行器按待办 id 记录已执行的动作，重复调用直接返回上次的结果。

可中断：进程在任一步被杀死后重启，待办要么还在 `claimed/` 等着被回收，要么已经在 `done/`，不存在中间态。状态只写在待办文件与记忆文件里，不驻留在内存。

## 不做什么

- 不决定「要不要打扰」，那由实例的 `rules/打扰分级.md` 决定
- 不解析业务语义，那是 `../models/` 与定义文件的事
- 不修改 `../../DNA/`

## 关键行为

| 场景 | 应有行为 |
|---|---|
| 已有守护进程在跑 | 报告持有者后退出，不抢占 |
| 锁的持有者已死 | 判定为残留，清理后重试一次 |
| 某个人格被别的进程占着 | 跳过该人格并记录，其他人格照常服务 |
| 续租失败 | 进入退让态，停止一切对外动作，随后退出 |
| 进程被强杀或断电 | 锁由操作系统释放；重启后若上次未正常停止，通过 IM 报告一次 |
| 连续重启超阈值 | 停止重启并告知用户，不陷入崩溃循环 |

## 命令

| 参数 | 含义 |
|---|---|
| `--user <user_id>` | 只服务指定人格，可重复 |
| `--all` | 服务 `personality/` 下全部实例 |
| `--status` | 打印每个 user_id 的持有者、启动时间、心跳 |
| `--takeover` | 显式夺取指定人格的锁，需确认 |

## 状态

`state/` 存放进程级状态，含 DNA 目录指纹与上次运行标记。它不入库。锁不在这里，锁在仓库之外的机器级运行时目录。
