# triggers

触发器回答一个问题：现在该不该请推理段看一次。它不回答该不该打扰用户。规格见 `../../DNA/触发器.md`，本文件说怎么实现。

## 三种输入，一个循环

| 源 | 实现要点 |
|---|---|
| 定时 | 读实例 `config.md` 的调度时刻表，到点触发。支持任意间隔，不受宿主定时器粒度限制 |
| 穿越 | 订阅感知量，记住上一次取值，本次跨过阈值时触发 |
| 外部 | 监听外部事件：宿主回调、消息推送、文件落地 |

三者共用一个事件循环，定时只是其中一路输入。

## 规则来自数据

触发条件不在代码里。装置实例时读两处：场景文件的「触发」段，与 `config.md` 的调度时刻表和阈值。改数据即改触发行为，代码不动。

## 产出

唯一产出是把一条待办写进实例的 `short-term/queue/pending/`，格式见 `../../DNA/触发器.md`。写完唤醒推理段；唤醒方式由宿主描述决定，触发器不认识具体是哪个软件。

## 要做与不要做

要做：时机判断、去重、写队列、唤醒推理段、回收超时未完成的领取。

不要做：不判断该不该打扰用户，不决定该怎么做，不执行任何对外动作。

## 去重

同一场景同一情境指纹只写一条待办。已有未消费的同类待办时，不新建，只在原待办上追加一条「再次满足」的时间记录。情境指纹取影响判断的那几个量，不取时间戳。

## 推理段不可用时

待办留在队列不丢，按剩余价值决定补做、保留还是标注过期。不可错过的动作按队列里保留的最近一次有效结论执行并标注降级，再不行退到画像里的固定经验值。

## 与其他模块

| 模块 | 关系 |
|---|---|
| `../runtime/` | 由它装载触发器并纳入同一个常驻进程，单实例约束一致 |
| `../../tools/sensors/` | 提供待订阅的感知量 |
| 宿主描述 | 提供唤醒推理段的方式 |
