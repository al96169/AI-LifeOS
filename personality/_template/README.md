# 新用户模板

复制本目录为 `personality/<user_id>/`，逐项填值，即得到一个新的助理实例。实例必须定义哪些内容，见 `../DNA/人格规范.md`。

## 填充顺序

初始化只填前四项，其余留到运行中按需补。

| 何时 | 位置 | 填什么 |
|---|---|---|
| 初始化 | `assistant.md` | 这个人格是谁、语气、服务对象 |
| 初始化 | `rules/` | 打扰分级、授权边界、代价评估 |
| 初始化 | `config.md` | 阈值、代价权重、节流、调度时刻、本机参数。阈值沿用默认值即可。「人格版本」保持模板里的值，升级时才改 |
| 初始化 | `skills/` | 该用户需要的场景，按 `../DNA/行为骨架.md` 派生 |
| 运行中 | `long-term/profile/` | 用户的稳定特征与偏好。不要向用户索要作息，它从行为与反馈里累积 |
| 运行中 | `long-term/capabilities.md` | 逐项申请能力。场景第一次真正需要时才申请，密钥写进 `long-term/secrets.env` |
| 运行中 | `long-term/schedule/` | 日程与承诺 |

初始化时不问用户两件事：作息与密钥。理由与补法见 `../DNA/初始化引导.md` 的「初始化时不问什么」。

## 约定

- `_template` 本身不参与运行，`user_id` 不得取这个名字
- `long-term/secrets.env` 只存在本机，本目录只保留列出变量名的 `secrets.example.env`
- 空目录用 `.gitkeep` 占位；运行时会写入的内容属于本机，不随模板分发

## 为什么这里没有示例内容

规则、技能与画像的写法由 `DNA/` 规定，不在这里放第二份。模板只提供结构与空位，避免派生出的实例跟着一份过时的样例走样。
