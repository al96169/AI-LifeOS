# 新用户模板

复制本目录为 `personality/<user_id>/` 填值即得新实例。必须定义哪些内容见 `../DNA/人格规范.md`。

## 填充顺序

| 何时 | 位置 | 填什么 |
|---|---|---|
| 初始化 | `assistant.md` `rules/` `config.md` | 是谁、打扰与授权边界、阈值与本机参数（阈值留默认）。只需忙「人格版本」保持模板值，升级才改 |
| 初始化 | `skills/` | 用户需要的场景，从空开始，按 `../DNA/行为骨架.md` 派生 |
| 运行中 | `long-term/profile/` `schedule/` `capabilities.md` | 偏好（勿索要作息）、日程、能力（场景首次真正需要时申请，密钥写 `secrets.env`） |

初始化不问两事：作息与密钥，理由与补法见 `../DNA/初始化引导.md`。

## 约定

`_template` 不参与运行，user_id 不得取此名；`secrets.env` 只本机，本目录只留列出变量名的 `secrets.example.env`；空目录用 `.gitkeep` 占位，运行时会写入的内容属本机。

## 为什么没有示例内容

规则、技能、画像的写法由 `DNA/` 规定，不在这里放第二份模板，避免派生实例跟着过时样例走样。
