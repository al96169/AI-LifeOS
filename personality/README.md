# personality（人格实例）

这一层说「这是谁」。DNA 是种子，这里是从种子长出来的那一株：某个具体用户的助理定义、它的规则与技能、它的长期与短期记忆。

## 一个用户一份

```
personality/
├─ _template/      新用户模板，按 DNA 规范派生
└─ <user_id>/      每个用户一份，互不可见
```

`user_id` 用 ASCII 小写字母、数字与连字符。新增一个用户的做法是复制 `_template` 并填值，不需要动 `DNA/`、`brain/`、`tools/` 的任何一行；若需要动，说明有个人信息漏进了共享层。

## 实例的构成

| 位置 | 内容 | 性质 |
|---|---|---|
| `assistant.md` | 助理定义：这个人格是谁、语气、服务对象、总原则 | 稳定 |
| `config.md` | 阈值、代价权重、节流、调度时刻、本机参数 | 常改，用来调行为倾向 |
| `rules/` | 打扰分级、授权边界、代价评估 | 半稳定，用户确认后才改 |
| `skills/` | 一个场景一份，按 `DNA/行为骨架.md` 书写 | 随场景扩展 |
| `long-term/profile/` | 用户的稳定特征与偏好 | 只增不改，由反馈沉淀而来 |
| `long-term/schedule/` | 日程、承诺、周期性约定 | 随现实更新 |
| `long-term/capabilities.md` | 能力状态与逐项配置 | 配置新资源时改 |
| `long-term/memory/` | 情景、语义、反馈 | 只增不改，运行时写入 |
| `long-term/secrets.env` | 密钥 | 只在本机，不入库 |
| `short-term/` | 当前情境、日志、缓存 | 随时过期，丢了不影响人格 |

长期与短期的分界看丢了之后要不要紧。密钥、偏好、安排跨会话成立且被反复引用，归长期；日志、当前情境、缓存归短期。

## 规则为什么在这里而不在 DNA

打扰分级、授权边界与代价权重本质上因人而异。同一条「下雨改打车」，对能容忍晚起的人和不能迟到的人应当给出不同的叫醒时刻。把它写进 DNA，就等于要求所有人共用一套容忍度。

## 技能为什么先放实例里

当前只有一个用户，五个场景以实例形式直接放在 `skills/` 下最直接。出现第二个用户时，再把共性逻辑提成 DNA 下的标准技能包，各用户在本地覆盖差异部分，避免复制四份天雨通勤。
