# personality（人格实例）

这一层说「这是谁」。DNA 是种子，这里是长出来的那株：某个用户的助理定义、规则、技能、长期与短期记忆。

```
personality/
├─ _template/      新用户模板，按 DNA 规范派生
└─ <user_id>/      每个用户一份，互不可见
```

新增用户=复制 `_template` 填值，不动 `DNA/brain/tools`；若需动，说明有个人信息漏进了共享层。

## 实例构成

| 位置 | 内容 | 性质 |
|---|---|---|
| `assistant.md` | 助理定义 | 稳定 |
| `config.md` | 阈值、权重、节流、调度时刻、本机参数 | 常改调行为 |
| `rules/` | 打扰分级、授权边界、代价评估 | 用户确认后改 |
| `skills/` | 一个场景一份 | 随场景扩展 |
| `long-term/profile/` | 用户稳定特征与偏好 | 只增不改，反馈沉淀 |
| `long-term/schedule/` | 日程、承诺、周期性约定 | 随现实更新 |
| `long-term/capabilities.md` | 能力状态与配置 | 配置新资源时改 |
| `long-term/memory/` | 情景、语义、反馈 | 只增不改，运行时写入 |
| `long-term/secrets.env` | 密钥 | 只本机，不入库 |
| `short-term/` | 情境、日志、缓存 | 随时过期 |

长短期分界看丢了要不要紧：密钥、偏好、安排反复引用归长期；日志、情境、缓存随时过期归短期。

## 规则为什么在实例而不在 DNA

打扰分级、授权边界、代价权重因人而异——同一条「下雨改打车」，对能晚起的人和不能迟到的人应给不同叫醒时刻。写进 DNA 等于要求所有人共用一套容忍度。

## 技能为什么先放实例

一份场景写的是「这个人此刻的处境」，换人该重写。项目不预置场景，`skills/` 从空开始随对话长出来；等出现第二个用户，再把共性逻辑提成 DNA 下标准技能包，避免一份场景维护几遍。
