# 守护进程

助理要全天候待命，得有一个进程长期活着；同一人格又不能被两个进程同时服务。本文件规定必须满足什么，不含代码。条文见 `铁律.md`。

## 硬约束

1. 一个人格在一台电脑上最多被一个进程服务
2. 一台电脑上最多一个守护进程，承载该机全部人格
3. 锁被他人夺走后，原持有者立即停止对外动作
4. 任何时候不得为「保证运行」跳过锁检查——宁可不起，不能起两份

## 两级锁

| 层级 | 保护对象 | 冲突后果 |
|---|---|---|
| 机器锁 | 整台电脑上的守护进程 | 重复调度、同提醒重复触发 |
| 人格锁 | 单个 user_id 的服务 | 同人格记忆互相覆盖 |

两级都要：机器锁挡得住重复自启，挡不住手工调试进程、另一份仓库副本、忘了关的旧版本；人格锁才保证「一人格一实例」。

## 锁的形态

优先操作系统独占锁（进程退出即释放，免疫崩溃残留）；否则退化锁文件，记录持有者 PID、启动时间、主机名、取得时刻。锁放机器级运行时目录（见下），不放在仓库里。判持有者是否存活不能只看 PID（会被复用）：按「独占锁→比对启动时间→看心跳时间戳」降级判定。

## 机器级运行时目录

仓库可能被复制到同机另一位置，两份副本各有各的目录——锁放仓库内等于没有锁。首选操作系统每用户运行时目录，否则 `用户主目录/.ai-lifeos/`。按名字建锁，机器锁一个、人格锁每个 user_id 一个。只存运行时状态，不入库。

## 启动流程

```
取机器锁（失败：持有者存活→报告退出不抢占；已死→判残留清理重试）
枚举 personality/ user_id（跳 _template），逐个取人格锁
  成功→装载该会话；失败→跳过该人格并记录，不影响其他
进入运行态
```

单个人格被占用不应拖垮整个守护进程。

## 心跳与退让

持有者每 `H` 秒刷新持有标记（默认 15s），容忍窗口取三倍（45s）。续租失败即锁被夺，立即退让：停止一切对外动作，不外呼、不发消息、不写记忆，只留日志后退出。防脑裂关键——两个实例各不退让的后果是重复外呼、记忆交替覆写，比短暂中断严重。

## 运行态

一个守护进程承载多 user_id 会话，状态不交叉（记忆、规则、技能、密钥互不可见）；各自按 `决策循环.md` 独立推进，一个用户失败不影响其他；守护进程维护心跳、看门狗、日志。

## 看门狗

主循环每轮打点，超 `W`（默认 120s）未打点判定卡死，主动退出交外部重新拉起（操作系统计划任务/服务管理器配置退出即重启）；连续重启超阈值（默认 5 次/10min）→ 停止重启并经 IM 告知，避免崩溃循环打扰。

## 优雅停止

停新触发 → 等在途动作（超 `T_drain` 默认 30s 放弃）→ 写回会话状态与记忆 → 释放人格锁与机器锁 → 退出。

## 异常退出与恢复

进程被强杀/断电时 OS 级锁自动释放，无需人工清理。重启后：读 `short-term/` 上次运行标记，若「未正常停止」经 IM 报告一次；错过的触发窗口只记录不追补——补做一次打扰比漏做更扰民；记忆完整性靠追加式写入，不依赖事务。

## 启动参数

| 参数 | 含义 |
|---|---|
| `--user <user_id>` | 只服务指定人格，可重复 |
| `--all` | 服务 `personality/` 下全部实例 |
| `--status` | 打印每个 user_id 的持有者、启动时间、心跳后退出 |
| `--takeover` | 显式夺取指定人格的锁（供运维，执行前需确认） |

`--status` 是排查「为什么没起来」的第一入口。

## 边界

跨机器的同一人格不在本约束内。若将来多台电脑服务同一人格，锁须换成带租约的协调服务，本设计失效，不能靠锁文件硬撑。心跳、看门狗、重启阈值是机器级默认值，各实例 `config.md`「守护」节可覆盖。
