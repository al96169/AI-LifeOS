# 行为骨架

场景定义的统一骨架，每份 `personality/<user_id>/skills/*.md` 按此书写。

```
# 场景：<名称>
- 场景ID：B-0X（示例，编号由实例自定）
- 触发：<条件 / 事件>
- 优先级：<高 / 中 / 低>
- 前提：<成立条件>
## 感知输入
## 决策规则
## 代价评估
## 动作（按打扰分级）
## 所需能力
## 兜底
## 示例
```

## 约定

跨场景共性放实例 `rules/`，场景文件只写差异；阈值一律写成可调参数（如 `P1`），实际取值集中在 `config.md`；时间用 24 小时制本地时间；任何感知缺失不得臆造，降级为「保持当前安排」并记录待补。

**触发行写的是「什么状态下值得判断一次」，不是「几点发」。不得写「定时」**——定时只是取数节奏，不构成开口的理由（`触发器.md`「触发不等于开口」）。场景默认静默：是否开口、开口说什么，每次都按现实情况、生活节奏、人格目标与记忆重算（`决策循环.md`「开口判定」）。

## 写的是判断方式，不是判断结果

一份场景写到什么程度算好，看它有没有把「该考虑哪些因素、按什么顺序比较」讲清楚，而不是有没有把条件与动作一一对应列成表。模型读场景是为了拿到判断起点，不是答案；每次触发重新采集、重新算代价，结论可能与文件示例相同或相反，条件一样而结论不同属正常。别写成判定表，别留「满足某条件就必须做某事」这类可照抄的捷径。

## 新增场景

项目不预置任何场景，实例 `skills/` 初始为空——场景随与用户对话长出来。加场景只需回答两问：该考虑哪些因素、按什么顺序比较；答不出说明还没想清楚，不是格式问题。

加一个场景三处都是数据、不改代码：`skills/` 新建一份按骨架写的 MD，`config.md` 补阈值/调度/感知订阅，`capabilities.md` 登记所需能力。
