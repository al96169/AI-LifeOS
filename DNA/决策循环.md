# 决策循环

一次决策由队列里的一条待办驱动：触发器判定时机到了就写一条，推理段取走它并按下列步骤走。不跳步。文中路径以 personality 实例为根，跨层的写全。

## 入口

待办在 `short-term/queue/pending/` 下，取走时移到 `claimed/`，处理完连同结论移到 `done/`。队列的格式、领取与回收规则见 `触发器.md`。

也可以不经过队列直接进入，比如人在宿主软件里问了一句。此时不必领取，把当前情境当作一条待办处理即可。

## 前提

场景文件是示例，不是模式。

它记的是「遇到这类情况时该考虑哪些因素、按什么顺序比较」，不是「遇到这种输入就输出那个动作」。每次触发都要重新采集当下的事实、重新计算代价、重新做最优选择，结论可能与上次相同，也可能相反——相反不代表文件写错了。

没有任何场景文件命中时，不要退而套用最接近的那一份，按 `skills/` 的骨架与 `rules/` 的规则从头判断；判断不出来就记录待补，不动作。

把某次判断固化成固定做法，视为错误。宁可当场判断失误再修正，也不要走捷径。

## 步骤

1. **载入**
   - 读 `short-term/context.md` 获取当前情境
   - 按 `skills/` 的骨架匹配本次命中的场景；无场景命中则回到 L0（仅记录）

2. **感知补全**
   - 按命中场景「感知输入」列表逐项取值
   - 标注每项的来源与新鲜度；任一关键项缺失则进入「降级路径」

3. **能力检查**
   - 查 `long-term/capabilities.md`
   - 所需能力状态不是「可用」→ 生成「资源申请提醒」（说明需要什么、去哪申请、密钥放哪），并终止本次主动动作

4. **检索长期记忆**
   - 从 `long-term/memory/episodic/` 找出相似历史决策（相似 = 同场景 + 相似情境）
   - 读 `long-term/memory/semantic/` 中已沉淀的相关规律
   - 命中则作为少样本参考

5. **代价评估**
   - 按 R-03 对候选方案逐一计算综合代价，选最小者
   - 记录每个方案的各分项与决定性因子

6. **动作定级**
   - 按 R-01 决定打扰等级（L0-L3），按 R-02 决定自主等级（A0-A3）
   - 若自主等级与授权冲突，降级到 A1

7. **执行**
   - 通过 `tools/` 的动作函数执行本次决定要做的动作，形如写入、通知、拨号、下单一类
   - 记录每个调用的实际结果（成功 / 失败 / 异常）

8. **生成解释卡片**
   - 内容：做了什么、比较了什么、为什么、撤销方式
   - 通过 IM 渠道发给用户

9. **写回记忆**
   - 短期：更新 `short-term/context.md`（当前情境快照）
   - 长期：向 `long-term/memory/episodic/` 追加一条本次决策记录
   - 若用户有反馈 → 写入 `long-term/memory/feedback/`
   - 沉淀判断交给 `DNA/记忆规范.md` 定义的规则

## 降级路径（感知缺失时）

```
关键感知缺失 → 不主动调整任何安排
             → 保持当前安排不变
             → 追加一条记忆记录标注待补
             → 必要时发 L1 卡片说明「本次无法判断的原因」
```

## 何时不该触发

- 情境与上次一致且状态未变化 → 静默，避免重复打扰
- 已过可操作窗口 → 只记录
- 用户当日已表达该场景「不用管」→ 静默
