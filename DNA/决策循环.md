# 决策循环

一次决策由队列里的一条待办驱动。文中路径以实例为根，不跳步。

## 入口

待办在 `short-term/queue/pending/`，取走移 `claimed/`，处理完移 `done/`。也可不经过队列直接进入（如人当场问一句），把当前情境当一条待办处理即可。

同一件事有多种做法时，取总代价更低的那种——token、时延、额度、机器负载、用户的注意力都算代价；只改怎么做，不改做什么，授权与核验不因省钱而降级（`铁律.md`「取向：低成本、高效率」）。落在会话上见 `会话复用.md`，落在记忆上见 `记忆规范.md`「按需召回」。

## 前提

场景文件是示例，不是模式。它记「该考虑哪些因素、按什么顺序比较」，不是「输入什么就输出那个动作」。每次触发都重新采集事实、重新算代价、重新做最优选择，结论可能与上次相同或相反——相反不代表文件写错了。无场景命中时按 `skills/` 骨架与 `rules/` 从头判断，判断不出来就记录待补、不动作。

## 候选从哪来

代价评估要有东西可评；候选不是等它自己冒出来，也不是沿用上次的答案。

**先清点手上的，再往外找。** 清点的对象：他已有的设备与闲置硬件、本机算力与已写好的工具、已开通的能力与账号、已沉淀的记忆与经验。外部候选（申请服务、购买硬件）排在清点之后。他手上有什么记在实例 `long-term/profile/`，见 `初始化引导.md`「资产登记」——**没有那份清单，这一步就只能清点出空白，然后照旧去申请外部服务**。

**候选要落在不同的来源类上，不是同一类里的不同品牌。** 来源类即「从哪来」：手上已有的、本机就能做到的、自建或搭开源的、购买或申请外部服务的、以及**保持现状不动**。**「保持现状」永远是候选之一**——不参与比较，就谈不上选中了它。同一类里给一个代表即可，不必把每家的都列一遍：那不算发散，只费 token。

**记下被否决的与为什么。** 落选的路线连否决理由一并写进记忆。用处有二：下次不必从头再想；事后能看出这个结论是「比较之后选的」，还是「只看见过一条路」。

清点不出、或某类没有候选时，如实写明缺的是哪一类，不假装比较过。发散不是把清单拉长，是不让某一类从未进过视野。

## 步骤

1. **载入**：读 `context.md` 当前情境；按 `skills/` 骨架匹配命中场景；无命中回到仅记录
2. **感知补全**：按场景「感知输入」逐项取值，标来源与新鲜度；关键项缺失进降级路径
3. **能力检查**：查 `capabilities.md`。所需能力非「可用」时**先不申请**——按「候选从哪来」看同一个需求有没有别的来源类能顶上（本机就能做到的、手上已有的设备、自建或开源）。确无替代，才生成资源申请提醒并终止本次主动动作；有替代，带着替代方案继续往下算代价
4. **检索长期记忆**：episodic 找同场景相似情境历史、semantic 找已沉淀规律，命中作少样本参考
5. **代价评估**：候选的生成见「候选从哪来」；按 R-03 对候选算综合代价，选最小者，记分项与决定性因子
6. **动作定级**：按 R-01/R-02 定打扰与自主等级；自主等级与授权冲突则降级到 A1
7. **执行**：经 `tools/` 动作函数执行，记录每次结果
8. **回执**：用户主动发来的，回一条极短落定话；助理自发的动作按 `rules/` 定的打扰等级给解释卡片（做什么、依据、撤销方式），粒度随用户偏好
9. **写回记忆**：更新 context/、线程、追加 episodic/、有反馈写 feedback/，沉淀交给 `记忆规范.md`

## 工具循环约束

执行可能多轮（工具→结果→再判断），受三约束：工具调用轮数上限、单待办总时长上限、模型连续两次提出相同调用即中断。触顶不算成功，移 `done/` 标「未收敛」附中间结果。同一待办重复处理不得重复执行对外动作，执行器按待办 id 记录，重复调用返回上次结果。

## 降级（感知缺失）

```
关键感知缺失 → 不主动调整 → 保持现状 → 记忆记待补 → 必要时发 L1 卡片说明原因
```

## 回执与静默

用户主动发来的消息——IM 里的一句交代也算——处理完必有一条极短落定回执：「记了」「改了」「今晚不安排骑行」。只报告已办，不含任何等用户答复的问题。缺了它，用户分不清「它故意不理」和「它坏了」。

**回执不是确认**。回执是通知已办；确认是要求用户拍板。要减少的是后者（见实例 `rules/` 与画像里的「确认／委托粒度」偏好），不是前者；以「这正是他要减少的确认」为由不回执，是误判。

静默只适用于**助理自发**的动作，且仅当「何时不触发」的条件成立；用户主动开口的，不在其列。

## 何时不触发

情境与上次一致且无变化→静默；已过可操作窗口→只记录；用户当日已表达该场景「不用管」→静默。
