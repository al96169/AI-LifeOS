# 宿主迁移

换宿主（换 Agent 软件、换机器、换系统）怎么走。它是**流程，不是事故**——能抱走的，插上就该能用。

## 什么时候算换宿主

推理段的承载变了：换了 Agent 软件、换了机器、换了系统，或原来那个宿主不再可用（被卸、被停、被锁）。三种情况都不算换宿主，各有各的走法：

| 情形 | 走哪 |
|---|---|
| 只换模型 | `人格规范.md`「换代」 |
| 只换渠道或外部供应商 | `人格规范.md`「换代」 |
| 首次部署，手上还没有实例 | `初始化引导.md` 全流程 |

## 两段：离场与入场

迁移只有两个动作窗口，中间那段时间人格不在跑。所以两段各自要有**可核的完成标志**，不能靠「应该没问题」。

### 一 · 离场（拔之前）

先让它自己收尾，人再动手：

1. **停新触发，等在途动作**——按 `守护进程.md`「优雅停止」走完，别直接断电或强杀
2. **状态落盘**：`context.md`、`threads/`、队列三条（pending / claimed / done）、长期记忆写回。**凡只活在会话内存里的，一律落盘**——宿主一换，会话内存就是垃圾（`会话复用.md` 不变量 2）
3. **未完成的活落成待办**：等凭据的、差依赖的、等对方回话的，一并进队列（`决策循环.md`「未完成的活」）。队列跟着实例走，它们不会丢
4. **写离场记录**：记清「拔走的是什么、当时在等什么、下次谁接着做」。没有它，入场方只能靠猜

### 二 · 入场（插之后）

1. **重核宿主能力**——按 `宿主能力要求.md`「评估候选宿主」过一遍。**这是唯一必须重做的核对**：宿主换了，能力结论就作废，登记里那句「满足」不能沿用
2. **重写路由登记**——`brain/router/` 下以自己名字命名的文件重写（反调命令、在线判定、人格加载、领取超时），格式见 `初始化引导.md`「路由登记」。换机器必须重写
3. **启动自检**——按 `守护进程.md`「启动自检」探三件：执行面可用、不被审批挂起、权限档与登记一致
4. **报告**——向用户报三件：我在哪个宿主上、能力比上次多了什么少了什么、之前那条未完成的活谁接着做

## 不做的事

**不重跑初始化。** 迁移不覆盖画像、规则、记忆、场景——那些是这个人格本身，跟宿主无关。凡「迁移之后画像变了」，一定是流程走错了。

**不改 `DNA/`。** DNA 只读，换宿主不该动它一个字（`铁律.md`）。新宿主带来的差异落在实例与登记里，不落在这里。

**不许静默迁移。** 迁移必须对用户可见，入场报告是它的一部分。用户不知道人格换了地方，就分不清「换完更贴了」和「它坏了」——这正是 `决策循环.md` 要求回执的同一条理由。
