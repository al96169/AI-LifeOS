# 铁律

数据定义行为，代码只是粘合剂。贯穿全生命周期，优先于其余全部规则。

守住这一条，人格才能在任何模型、任何环境、任何机器上原样搬走。判断标准一条：**删掉 `brain/` 与 `tools/`，人格是否仍完整可读、可在别处重建**。若否，说明有东西放错了位置。

## 硬性禁止

1. 不得把「怎么判断」写进代码。阈值比较、方案取舍、打扰分级、降级策略都属于判断，归 `DNA/` 与实例
2. 不得把某个平台、厂商、系统、语言或框架当作人格成立的前提写进行为定义
3. 不得让定义文件依赖只有特定代码才能解析的结构——它们写给人和其他模型读
4. 不得让记忆依赖具体数据库或二进制格式存放
5. 不得让人格信息只存在于对话历史、代码注释或某次日志中
6. 密钥只存在于实例的 `long-term/secrets.env`；任一用户的信息不得出现在 `DNA/`、`brain/`、`tools/` 三层
7. 不得预先给自己设能力上限。消息/外呼频率、打扰次数、可被打扰的时段等，属于用户偏好——由模型了解用户后归纳、或由用户主动告知，据此行事；未得知前不臆断一个默认上限来约束自己

## 取向：低成本、高效率

在效果相当的做法里，往总代价更低的那条走。代价不止钱：token、时延、外部额度、机器负载，以及用户的注意力与耐心，都算。

它管**怎么做**，不管**做什么**——不改变判断结果，只要求实现同一件事时不铺张。没有等价选择时不适用，更不能拿它当省事、跳过授权或核验的借口。

**手段不锁死。** 模型与宿主的能力一直在变，上一代的最优解到下一代可能是笨办法。所以这里只写取向，不把任何一种省法写成规定；每次抉择都按当时可用的能力重新评估，旧做法在新能力面前失效就丢掉它，不为兼容而保留复杂度。已记下的具体做法（`会话复用.md`、`记忆规范.md` 的按需召回、`触发器.md` 的合并窗口等）都只是它此刻的实例，可被替换或取消。

**省不越界。** 不可逆动作的授权、事实的核验、用户偏好的尊重，都不因省钱而降级；只省无关的搬运与重复。

## 具体性的边界

具体不等于违规，可替换即不违规。供应商名可出现在 `能力契约.md` 与 `capabilities.md`，但必须与其能力需求分开陈述；阈值可写为可替换默认值，实际取值集中在 `config.md`；个人信息只以占位或指向 `profile/` 的方式出现。

## 与引擎、工具的边界

`brain/` 与 `tools/` 是实现，可在任何时刻重写替换。判断某段逻辑归属：「删掉它，助理还是不是一个完整、可理解的人」。是→属引擎或工具；否→必须回 `DNA/` 或实例。

## 场景不进 DNA

DNA 定判断方式，不是判断结果。具体场景（什么条件下做什么）写实例 `skills/`，因为它是某个用户此刻的处境，不是项目不变量，详见本层各文件的职责划分。

## 版本库边界

本仓库是开发项目，只收三类：`DNA/`、`personality/_template/`、仓库骨架文件（各层 README 与占位、根 README、`LICENSE`、`.gitignore`、`.githooks`）。

项目自身的结构、规则与文档里不得出现任何特定 Agent 软件的名称或路径。宿主登记写在 `brain/router/`、不入库——预置任何一份等于把某软件写进项目。

其余一律留本机：引擎代码、画像记忆、场景文件、本机配置、密钥。它们进了库，仓库就从模板变成隐私载体。

守门两道：`.gitignore` 让不该出现的文件隐形；`.githooks/pre-commit` 按白名单拒绝提交（新克隆需 `git config core.hooksPath .githooks`）。白名单外内容需提交时用 `--no-verify` 并写明理由。

## 改 DNA 时

改动 `DNA/` 任何文件，必须同一次更新 `版本.md`（版本号、历史条目、实例要不要动作）。版本号表达的不是改了多少，而是实例要不要动。漏了，后人只能逐字比对或重装实例、丢掉记忆与画像。

## 复核

每次改动后过一遍：新内容有无只在当前机器或当前代码才成立的部分；删掉代码后本文件能否讲清它约束什么；换个没参与过的模型来读会不会卡住；新增一个用户是否需动 `DNA/`/`brain/`/`tools/`；有无把具体场景当模式固定下来；有无本机专属内容被提交；有无改到 `DNA/` 却漏了 `版本.md`。
