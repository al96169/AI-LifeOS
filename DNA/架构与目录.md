# 架构与目录

四层划分：`DNA/` 说这是什么，`personality/` 说这是谁，`brain/` 负责把定义读进来并推进决策，`tools/` 负责把决定落成动作。

划分依据是变更频率与归属：DNA 几乎不变，personality 每天都在变，brain 与 tools 只在开发时变。

## 目录总览

```
AI-LifeOS/
├─ DNA/               项目定义，运行时只读
├─ personality/       人格实例，一用户一份
├─ brain/             运行时引擎
└─ tools/             动作与脚本
```

上图是机器上的完整结构。仓库只收录其中的 `DNA/`、`personality/_template/` 与各层的结构说明，带用户数据的实例目录、引擎与工具的代码都不入库，条文见 `铁律.md` 的「版本库边界」。

## 四层职责

| 层 | 是什么 | 谁改 | 随用户变化 |
|---|---|---|---|
| `DNA/` | 项目定义，人格的种子 | 只在项目演进时由人改，运行时只读 | 否 |
| `personality/` | 人格实例与其记忆 | 运行时持续写入 | 是 |
| `brain/` | 运行时引擎：主循环、模型、触发器 | 开发时改 | 否 |
| `tools/` | 手脚：动作、渠道、感知、脚本 | 开发时改 | 否 |

## personality

```
personality/
├─ _template/             新用户模板，按本目录规范派生
└─ <user_id>/             每个用户一份，互不可见
   ├─ assistant.md        助理定义
   ├─ config.md           阈值、权重、节流、调度时刻、本机参数
   ├─ rules/              打扰分级、授权边界、代价评估
   ├─ skills/             一个场景一份
   ├─ long-term/          长期记忆，只增不改
   │  ├─ secrets.env      密钥，不入库
   │  ├─ profile/         用户特征与偏好
   │  ├─ schedule/        日程、承诺、周期性约定
   │  ├─ capabilities.md  能力状态与逐项配置
   │  └─ memory/          episodic / semantic / feedback
   └─ short-term/         短期记忆
      ├─ context.md       当前情境窗口
      ├─ queue/           待办队列：pending / claimed / done
      ├─ logs/            运行日志
      └─ cache/           感知缓存
```

## brain

```
brain/
├─ runtime/          主循环、会话装配、守护进程、状态加载与写回
├─ models/           模型接入与提示装配
└─ triggers/         触发：定时、穿越、外部，产出待办
```

## tools

```
tools/
├─ actions/          把决定落成动作：写入、通知、拨号、下单一类
├─ channels/         与用户对话的渠道适配
├─ sensors/          感知采集：外部数据与本机状态
├─ lib/              配置与密钥读取、缓存、日志
└─ scripts/          一次性与运维脚本
```

## 加载顺序

一次决策按此顺序读入上下文，不跳步。下列路径以 personality 实例为根：

1. `assistant.md` — 身份与总原则，常驻系统提示
2. `rules/` — 打扰分级、授权边界、代价评估
3. `long-term/profile/` — 用户是谁
4. `skills/` — 命中哪个场景就加载哪份
5. `short-term/context.md` — 此刻的情境窗口
6. `long-term/capabilities.md` — 所需能力是否可用
7. `long-term/memory/` — 按需检索相似历史与已沉淀规律
8. `DNA/决策循环.md` — 决策的执行步骤

接手、重建或换代时先读 `DNA/人格规范.md`。

## 多用户

| 维度 | 做法 |
|---|---|
| 隔离 | 用户专属内容只在 `personality/<user_id>/` 下 |
| 命名 | `user_id` 用 ASCII 小写字母、数字与连字符，避开中文路径在工具链上的问题 |
| 密钥 | 每用户一份 `secrets.env`，互不可见，均不入库 |
| 装载 | 运行时按 user_id 加载，一个进程可服务多用户，记忆、规则、技能、密钥不跨用户共享 |
| 新增用户 | 复制 `_template` 并填值，不改 `DNA/`、`brain/`、`tools/` |

## 机器级运行时目录

锁与守护进程状态不放在仓库里，放在机器级运行时目录：首选操作系统提供的每用户运行时目录，没有则退到用户主目录下的 `.ai-lifeos/`。

仓库可能被复制到同一台电脑的另一个位置，两份副本各有各的目录，锁放在仓库内等于没有锁。这个目录只存运行时状态，不属于人格数据，也不入版本管理。

两级锁、心跳与退让规则见 `守护进程.md`。

## 引擎与工具的接口契约

工具层向引擎承诺下列语义，实现语言与形态自由。

> 下列签名取自当前实例，属示例。新增能力时按同样的写法在 `tools/` 里补上接口，不要受这份清单限制。

```
# 感知
get_rain_forecast(place, hours) -> {hourly_probability, freshness}
get_eta(from, to, mode) -> {minutes_p10, minutes_p90, freshness}
get_calendar(date) -> [events]
get_battery() -> {percent, charging}
get_foreground_activity() -> {process, title, duration}

# 执行
set_alarm(time, label)
send_im(text, card=None)
critical_notify(title, body)
call_and_speak(phone, script)
place_order(shop, items, constraints)

# 通路
chat(messages, tools) -> {tool_calls | content}
```

每个动作函数返回结构化结果，供引擎写回记忆：

```
{ok: bool, action: str, detail: {...}, error: str|null, executed_at: ts}
```

失败不得静默吞掉，必须回传，由引擎决定是否降级、是否记录。
