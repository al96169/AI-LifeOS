# 架构与目录

四层：`DNA/` 说这是什么，`personality/` 说这是谁，`brain/` 把定义读进来推进决策，`tools/` 把决定落成动作。划分依据变更频率与归属：DNA 几乎不变，personality 每天变，brain/tools 只在开发时变。

```
AI-LifeOS/
├─ DNA/               项目定义，运行时只读
├─ personality/       人格实例，一用户一份
├─ brain/             运行时引擎，含登记宿主的路由层
└─ tools/             动作与脚本
```

机器上还有实例目录、引擎代码；仓库只收 `DNA/`、`personality/_template/`、各层结构说明，见 `铁律.md`。

## personality

```
personality/
├─ _template/             新用户模板
└─ <user_id>/             每个用户一份，互不可见
   ├─ assistant.md        助理定义
   ├─ config.md           阈值、权重、节流、调度时刻、本机参数
   ├─ rules/              打扰分级、授权边界、代价评估
   ├─ skills/             一个场景一份
   ├─ long-term/          长期记忆，只增不改
   │  ├─ secrets.env      密钥，不入库
   │  ├─ profile/         用户特征、偏好与资产（资产与设备.md）
   │  ├─ schedule/        日程、承诺、周期性约定
   │  ├─ capabilities.md  能力状态与配置
   │  └─ memory/          index.md + episodic / semantic / feedback
   └─ short-term/         短期记忆
      ├─ context.md       当前情境窗口
      ├─ threads/         对话线程，一渠道一段，续接会话的落点
      ├─ queue/           待办队列：pending / claimed / done
      ├─ logs/            运行日志
      └─ cache/           感知缓存
```

## brain

```
brain/
├─ runtime/          主循环、会话装配、守护进程、状态读写
├─ models/           自建推理段的模型接入与提示装配；交给宿主则由宿主代劳
├─ triggers/         触发：定时、变化、外部，产出待办
└─ router/           路由层：登记各宿主反调方式，唤醒其一
```

## tools

```
tools/
├─ actions/          落成动作：写入、通知、拨号、下单一类
├─ channels/         与用户对话的渠道适配
├─ sensors/          感知采集：外部数据与本机状态
├─ lib/              配置与密钥读取、缓存、日志
└─ scripts/          一次性与运维脚本
```

## 一次安排的主链路

```
感知变化 → 触发器 → 待办 → 路由层 → 模型
                                    读人格 → 读记忆与偏好 → 当场比较方案
                                           ↓
                                    决定动什么 → 工具落地 → 写回记忆
```

链上代码只出现在三处：取回感知、把待办递到模型、把决定落成动作。中间「要不要动、动哪个、怎么说」不存在代码形态，只存在于定义文件与模型的当场判断。因此没有「实现某个场景」这回事——加场景就加一份 `skills/*.md`，改判断就改定义文件。

## 加载顺序

一次决策按此读入上下文，不跳步（以实例为根）：
assistant.md → rules/ → long-term/profile/ → 命中的 skills/ → short-term/context.md → long-term/capabilities.md → `long-term/memory/index.md`（先定位）→ 按定位拉相关条目原文 → `DNA/决策循环.md`。

记忆不进默认上下文的部分：episodic 全文、旧条目、feedback 原始，按需取，见 `记忆规范.md`「按需召回」。此加载顺序用于冷启动 / 接管 / 会话断裂；**会话内续时不整套重载**——复用会话只追加增量，见 `会话复用.md`。加载顺序的前段（assistant / rules / profile / skills / capabilities / 未变及的 memory 索引）多轮之间基本不变，属**静态可缓存段**——宿主要省 token 就按此顺序把不变段排前、变化段排后，并开上下文缓存（prompt caching / KV cache）；命中缓存按折扣计费。缓存进没进、打折不打折由宿主决定，人格定义不假设它存在。

接手、重建、换代先读 `DNA/人格规范.md`。

## 多用户

用户专属内容只在 `personality/<user_id>/` 下；`user_id` 用 ASCII 小写、数字、连字符；密钥每用户一份；一个进程可服务多用户，记忆、规则、技能、密钥不跨用户共享；新增用户=复制 `_template` 填值，不改 `DNA/brain/tools`。

## 机器级运行时目录

锁与守护状态放仓库之外：首选操作系统每用户运行时目录，否则用户主目录下 `.ai-lifeos/`。仓库可能被复制到同机另一位置，锁放仓库内等于没有锁。此目录只存运行时状态，不入库。规则见 `守护进程.md`。

## 接口契约

工具层向引擎承诺下列语义，形态自由。

> 签名取自当前实例，属示例。新增能力按同样写法补接口。

```
# 感知
get_rain_forecast(place, hours) -> {hourly_probability, freshness}
get_eta(from, to, mode) -> {minutes_p10, minutes_p90, freshness}
get_calendar(date) -> [events]
get_battery() -> {percent, charging}
get_foreground_activity() -> {process, title, duration}
get_latest_dna_version() -> {latest_version, source_freshness}  # 更新检查（见 更新.md）
# 执行
set_alarm(time, label)
send_im(text, card=None)
critical_notify(title, body)
call_and_speak(phone, script)
place_order(shop, items, constraints)
# 通路
chat(messages, tools) -> {tool_calls | content}
```

每个动作返回 `{ok, action, detail, error, executed_at}`，供写回记忆。失败不得静默吞掉，由引擎决定降级。
