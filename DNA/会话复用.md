# 会话复用

推理段怎么持有模型会话。不变量：同一对话线程内**复用会话**，不重复注入整套人格——省 token 且首 token 快；复用不等于放弃可移植，关键状态照旧落盘，任一会话失效可原样恢复。

## 不变量

1. **线程内复用**：同一对话线程的后续轮次延续当前模型会话，不做新的冷启动。人格定义交给宿主按「系统提示 / 静态前缀」缓存，每轮只追加：当前 `context.md` 摘要、当轮事件或请求、命中场景、需复核的事实。不把 assistant / rules / profile / 记忆 整袋重新注入。
2. **状态在磁盘，不只会话内存**：会话在续，但 `context.md` 与 `long-term/memory/` 照旧写回、按需求读。会话被宿主回收、或换模型、换宿主，靠磁盘原样恢复，不依赖 provider 侧的对话历史。会话复用省的是「重复注入静态前缀」，不是省「该查证的查证」——查证照旧（见 `记忆规范.md`「按需召回」）。
3. **快慢两轨**：闲聊、确认、回执走快轨——复用会话、少注入、秒回一句；要安排、要感知、要落动作走慢轨——按 `架构与目录.md` 加载顺序补齐情境，仍尽量只带命中项与索引定位的原文。
4. **不新增框架**：宿主支持什么复用形态（续聊、多轮工具循环、流式）就按其形态复用；只支持一次性，就遵守一次性并在一次内做全。本约定不改代码，是给推理段的执行约定。

## 结论

- 有可延续会话 → 在上面追加增量，不重新接管。
- 会话断裂 / 换宿主 / 恢复 → 才走 `人格规范.md` 接管，把 `context.md` 与相关记忆读作会话种子。
- 一次会话内需多次感知 / 多轮工具 → 在同一会话内延续，中间态留在 `context.md`，不把每次工具结果当成一次全新冷启动。
