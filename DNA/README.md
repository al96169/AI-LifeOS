# DNA（项目定义）

这一层定义「这是什么」，不定义「这是谁」——一个助理人格的种子：拿到 DNA 与一份 personality 实例，就能在任何环境重建等效助理。

## 只读

人格运行时绝不修改本目录：以只读方式加载、代码无写入路径；每次启动算一次目录指纹记在 `brain/runtime/state/` 下，与上次不一致则向用户报告（意味着有人手工改过或发生过重建）。要调行为倾向改 personality 实例，要改机制规则才改这里。

## 文件导览

| 文件 | 何时读 |
|---|---|
| `初始化引导.md` | 新环境初始化时 |
| `宿主能力要求.md` | 挑选/评估宿主时 |
| `铁律.md` | 动手改动任何一层前 |
| `版本.md` / `升级指导.md` | 改 DNA 前；检测到升级、整理给用户的执行步骤时 |
| `更新.md` | 理解更新检查与协商、设置更新策略时 |
| `人格规范.md` | 想弄清这个人格为何存在、服务到哪为止、自保的边界、接手、重建、换代时 |
| `架构与目录.md` | 了解结构时 |
| `决策循环.md` | 实现或审查运行时 |
| `行为骨架.md` | 增改场景时 |
| `记忆规范.md` | 实现或审查记忆读写 |
| `守护进程.md` | 实现或审查常驻服务 |
| `触发器.md` | 实现或审查触发与唤醒 |
| `能力契约.md` | 申请能力、换供应商时 |

## 规范与实例

这里只写规范与不变量：说「阈值必须可替换」不说「阈值是 0.6」；说「需要某类感知」不说「用某家服务」。具体取值、供应方、密钥一律属 personality 实例。

## 场景不进这里

场景是某个用户此刻的处境，写在实例 `skills/`。本目录只规定场景怎么写，不规定某场景怎么判断。确需举例时标「示例」并写明不构成模式，条文见 `铁律.md`。

## 不变量

不含密钥、账号、坐标、手机号；不含针对单用户的偏好或安排；不含具体场景（确需举例标示例）；不含只有某套代码才能解析的结构。
