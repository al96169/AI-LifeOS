# DNA（项目定义）

这一层定义「这是什么」，不定义「这是谁」。它是一个助理人格的种子：拿到 DNA 与一份 personality 实例，就能在任何环境重建出等效的助理。

## 只读约定

人格运行时绝对不修改本目录。落实方式有两条：运行时以只读方式加载，代码中不存在任何指向这里的写入路径；每次启动计算一次目录指纹并记在 `brain/runtime/state/` 下，与上次不一致时向用户报告，因为那意味着有人手工改过，或者发生过一次重建。

要调某个人的行为倾向，改 personality 实例；要改机制的规则，才改这里。

## 读什么

| 文件 | 内容 | 何时读 |
|---|---|---|
| `初始化引导.md` | 交给 Agent 软件的引导语、初始化步骤、建议启用的能力、路由登记格式 | 在一个新环境初始化时 |
| `宿主能力要求.md` | 一个 Agent 软件要当推理段必须满足哪些能力，缺项时怎么降级 | 挑选或评估宿主时 |
| `铁律.md` | 数据定义行为；可移植性条文与复核方式 | 动手改动任何一层之前 |
| `人格规范.md` | 一个实例必须定义什么；接管协议、重建协议 | 接手、重建、换代时 |
| `架构与目录.md` | 四层职责、目录总览、加载顺序、多用户规范、接口契约 | 了解项目结构时 |
| `决策循环.md` | 每次决策的固定步骤 | 实现或审查运行时 |
| `行为骨架.md` | 场景行为的统一骨架与编号约定 | 新增或修改场景时 |
| `记忆规范.md` | 记忆分层、沉淀条件、归档阈值 | 实现或审查记忆读写 |
| `守护进程.md` | 单实例约束、两级锁、心跳与退让、自愈 | 实现或审查常驻服务时 |
| `触发器.md` | 三种触发源、待办队列、去重、离线降级、派发 | 实现或审查触发与唤醒时 |
| `能力契约.md` | 抽象能力需求与降级规则，供应方无关 | 申请能力、更换供应商时 |

## 规范与实例

这里只写规范与不变量。它说「阈值必须写成可替换的参数」，不说「阈值是 0.6」；说「需要某类感知数据」，不说「用某家服务」。具体取值、具体供应方、密钥一律属于 personality 实例。

## 场景不进这里

场景是某个用户此刻的处境，不是项目的不变量，写在实例的 `skills/` 里。本目录只规定场景该怎么写，不规定某个场景该怎么判断。

确需举例时，标注为「示例」，并写明该示例不构成模式：模型不得固化场景模式，每次触发都要重新采集事实、重新计算代价、重新做最优选择，结论可能与上次相同，也可能相反。条文见 `铁律.md`。

## 不变量

- 本目录不含任何密钥、账号、坐标、手机号
- 本目录不含任何针对单个用户的偏好或安排
- 本目录不含具体场景；确需举例时标注为「示例」并写明不构成模式
- 本目录不含只有某套代码才能解析的结构
