# 初始化引导

一份可以直接交给任何 Agent 软件的引导语，以及它背后的步骤。适用于刚拿到这个项目、准备让它跑起来的环境。

## 引导语

下面这段可以原样交给 Agent 软件，或作为它的第一条指令。

> 这个仓库是一个生活助理的定义，不是一个可执行程序。你是它的推理段，不是它的作者。
>
> 请按顺序做三件事，做完停下向我汇报。
>
> 第一，读 `DNA/README.md`、`DNA/铁律.md`、`DNA/架构与目录.md`、`DNA/人格规范.md`。最后一份列出了接手前必须先弄明白的问题，答不出来就先别往下做。
>
> 第二，读 `personality/` 下除 `_template` 之外的实例。没有实例就复制模板建一份，填 `assistant.md`、`config.md` 与 `rules/`。
>
> 第三，把自己登记进路由层：在 `brain/router/` 下写一份以你自身名字命名的文件，写清怎么反向调用你、你怎么读到人格、哪一项可以判定你在不在线。格式见 `DNA/初始化引导.md` 的「路由登记」。
>
> 两条要守住：`DNA/` 只读；你的配置与登记都写在本机，不进版本库。

## 初始化步骤

| 步 | 做什么 | 完成标志 |
|---|---|---|
| 1 | 读 DNA 四份基础文件，用 `人格规范.md` 的自检问题验自己 | 那几个问题都答得出 |
| 2 | 确认或建立实例，填 `assistant.md`、`config.md`、`rules/` | `config.md` 里没有「待填」 |
| 3 | 申请前四项能力，密钥写 `long-term/secrets.env` | 四项状态为「可用」 |
| 4 | 把自己登记进路由层 | `brain/router/` 下有你写的那份，字段齐全 |
| 5 | 在自己软件里配好入口：读哪份文件、从哪句话开始接管 | 说一句启用人格，你能按自检问题答出来 |
| 6 | 验证反向调用 | 从命令行触发一次，你能收到、处理，并把结论写回队列 |

第 4 步是这个项目与宿主之间唯一的接线动作。做完它，触发器才找得到你。至于你在自己软件里怎么配置、用什么形态存在、是常驻进程还是一次性调用，项目不关心，也不需要知道。

## 初始化后建议启用的能力

前四项是跑通一个场景的最低要求，已经排在实例能力清单的前面。之后建议优先打通下面这些。

| 优先 | 能力 | 为什么建议早接 |
|---|---|---|
| 1 | 与用户对话 | 消息渠道是唯一的双向入口。缺它，助理只能单向打扰，用户无法回一句「今晚破例」或「这次太早了」，反馈闭环不成立，记忆也就无从沉淀 |
| 2 | 本机感知与本地执行 | 让助理看得见本地状态、写得进系统闹钟。缺它时叫醒只能靠外呼，设备问题也无法预判 |
| 3 | 语音外呼叫醒 | 把提醒升级成真电话。消息会被静音、会被忽略，电话不会 |
| 4 | 代下单 | 风险最高，涉及付款，放最后。先用最小金额跑通全链路与撤销，再日常使用 |

第 1 项要从三个候选里挑一个接：企业微信、QQ、飞书，选开发量最小的那个先跑通，其余以后按需再加。个人微信没有官方机器人接口，第三方方案有封号风险，不采用。

## 路由登记

路由层是触发器与宿主之间唯一的接线点，位置在 `brain/router/`。初始化时由 Agent 软件写一份自己的登记，文件名取自己的名字。

```
# 路由：<宿主名>
- 反调命令：<带 {id} 占位符的命令模板>
- 在线判定：<一条命令或一个条件>
- 人格加载：<它读哪些文件、从哪句话开始接管>
- 领取超时：<默认 10 分钟>
- 登记时刻：<时间>
```

`{id}` 是待办 id，由触发器填充。写完这几项就够，不必描述你内部怎么实现。

可以登记多个宿主。路由层按在线判定筛出可用的，按登记顺序取第一个；都不在线时按 `触发器.md` 的离线规则处理。

登记文件不进版本库。它含本机路径与在线判定方式，换机器要重写，所以由初始化动态生成，不由仓库预置。
