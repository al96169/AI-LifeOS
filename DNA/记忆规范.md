# 记忆规范

连接短期记忆与长期记忆的闸门，回答一个问题：什么样的事情才配写进「关于我」的长期记忆。

文中路径以 personality 实例为根。

## 两层记忆

| 层 | 位置 | 性质 |
|---|---|---|
| 短期 | `short-term/` | 易失，记「此刻」；随天或周期滚动过期 |
| 长期 | `long-term/memory/` | 持久，记「你是谁」；只增不改 |

分界看丢了之后要不要紧：日志、当前情境、缓存随时过期，丢了不影响人格；画像、规律、反馈跨会话成立且被反复引用，丢了人格就不完整。

## 沉淀通道

```
短期情境 ──(反复出现 / 被反馈确认)──▶ 情景记忆 ──(多次一致的归纳)──▶ 语义记忆
   ↑易失                                                                    │
   └────────────────── 下次决策按需召回（少样本）──────────────────────────┘
```

## 升级条件

事件从短期升级为长期，必须满足下列之一，绝不因单次事件升级：

| 目标层 | 条件 |
|---|---|
| `long-term/memory/episodic/` | 一次被执行的决策落一条记录（这是默认行为，不算「沉淀」） |
| `long-term/memory/semantic/` | 同一模式在情景记忆中出现次数不少于 `N_same`（默认 3），或用户在 IM 中明确确认过一次 |
| `long-term/profile/` | 该规律涉及的是稳定偏好，例如画像里的某一项，且已被用户确认后才写入 |

## 写入时机

- 每天固定一个「记忆整理」时刻（默认 03:00，低打扰时段）做一次批量沉淀判断
- 也可在用户明确给出反馈时立即触发单条处理

## 衰减与遗忘

- 短期：到期即清，不做归档
- 长期情景记忆：从未被召回、且超过 `T_decay`（默认 90 天）的低价值条目移入归档，不再参与检索
- 语义记忆与画像：不自动衰减，只在用户确认后修改

## 修正流程（只增不改）

长期记忆不允许直接覆写，修正走追加：

1. 用户反馈写入 `long-term/memory/feedback/`，含日期、原结论、新结论、原因
2. 沉淀逻辑在整理时基于最新反馈重算画像与规律
3. 重算结果写为新条目，并在文件头标注「替代自 <旧条目>」
4. 旧条目保留，形成可追溯的演化史

## 不变量

- 短期内容永不直接变成画像
- 一次异常（示例：某天意外熬夜、某天临时改换通勤方式）不得改写长期画像
- 任何自动生成的画像改动都必须可回溯到具体的反馈条目
- 助理不得自动修改 `long-term/profile/` 与 `rules/`，只能提案，由用户确认
- 非真实决策产生的条目（演练、联调、测试）必须标注来源与性质，不得作为少样本被召回
