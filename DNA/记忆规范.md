# 记忆规范

短期与长期记忆之间的闸门：什么样的事才配写进「关于我」的长期记忆。

## 两层

| 层 | 位置 | 性质 |
|---|---|---|
| 短期 | `short-term/` | 易失，记「此刻」；随天或周期滚动过期 |
| 长期 | `long-term/memory/` | 持久，记「你是谁」；只增不改 |

分界看丢了要不要紧：日志、情境、缓存随时过期故归短期；密钥、偏好、画像、规律反复引用故归长期。

## 沉淀通道

```
短期情境 ──(反复出现 / 被反馈确认)──▶ 情景记忆 ──(多次一致的归纳)──▶ 语义记忆
    ↑易失                                                               │
    └──────────────── 下次决策按需召回（少样本）────────────────────────┘
```

## 升级条件（不因单次事件升级）

| 目标层 | 条件 |
|---|---|
| episodic/ | 一次被执行的决策落一条记录（默认行为，不算沉淀） |
| semantic/ | 同模式在情景记忆出现 ≥ `N_same`（默认 3）次，或用户明确确认过一次 |
| profile/ | 涉及稳定偏好且已被用户确认后写入 |

## 时机

每天固定「记忆整理」时刻（默认 03:00）做一次批量沉淀；用户明确反馈时立即单条处理。

## 衰减

短期到期即清不归档。长期情景记忆：从未被召回且超 `T_decay`（默认 90 天）的低价值条目归档，不再参与检索。语义与画像不自动衰减，只在用户确认后修改。

## 修正：只增不改

长期记忆不覆写，修正走追加：反馈写入 `feedback/`（日期、原结论、新结论、原因）→ 整理时重算 → 结果写新条目并标「替代自 <旧条目>」→ 旧条目保留形成演化史。

## 不变量

短期内容永不直接变成画像；一次异常（意外熬夜、临时换通勤）不得改写长期画像；任何自动画像改动须可回溯到具体反馈；助理不得自动改 `profile/` 与 `rules/`，只能提案由用户确认；非真实决策产生的条目（演练、联调、测试）须标注来源与性质，不得作为少样本被召回。
