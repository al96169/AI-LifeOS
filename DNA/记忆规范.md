# 记忆规范

短期与长期记忆之间的闸门：什么样的事才配写进「关于我」的长期记忆。

## 两层

| 层 | 位置 | 性质 |
|---|---|---|
| 短期 | `short-term/` | 易失，记「此刻」；随天或周期滚动过期 |
| 长期 | `long-term/memory/` | 持久，记「你是谁」；只增不改 |

分界看丢了要不要紧：日志、情境、缓存随时过期故归短期；密钥、偏好、画像、规律反复引用故归长期。

## 沉淀通道

```
短期情境 ──(反复出现 / 被反馈确认)──▶ 情景记忆 ──(多次一致的归纳)──▶ 语义记忆 ──(反馈验证)──▶ 经验
    ↑易失                                                                                │
    └──────────────────────── 下次决策按需召回（少样本）──────────────────────────────────┘
```

## 按需召回

`铁律.md`「取向：低成本、高效率」在记忆上的一处实例。长期记忆随使用只增，每次全量灌进上下文越吃越贵。规则：**默认不整袋读长期记忆**，只带两层——semantic/ 与最近可操作窗口内的 episodic 概要；更老、更细的条目不进默认上下文，靠 `long-term/memory/index.md` 定位后按需取原文。

- **索引先行**：`index.md` 给每条记忆登记一行——时间、主题、场景、相关实体、一句话结论、指向原文。决策先读索引判定位，必要时读原文；没带全量就把「带了什么」如实写明。
- **检索不到不臆造**：相关条目没定位到，按缺失处理并记录，不凭训练记忆或常识代填。
- **省搬运不省查证**：涉及判断的事实照常核验，只省「无关历史」的搬运，不省必须的核对。

## 升级条件（不因单次事件升级）

| 目标层 | 条件 |
|---|---|
| episodic/ | 一次被执行的决策落一条记录（默认行为，不算沉淀） |
| semantic/ | 同模式在情景记忆出现 ≥ `N_same`（默认 3）次，或用户明确确认过一次 |
| 经验 | 语义结论含「做法 / 教训」且 ≥ `N_same` 次一致，并至少一次被反馈验证；或用户明确确认 |
| profile/ | 涉及稳定偏好且已被用户确认后写入 |

**画像条目标来源。** 每条注明来自哪一类，三类可信度不同，不得混同：

| 来源 | 用法 |
|---|---|
| 他说的 | 可直接用；随口一句写进画像前先确认一次（`初始化引导.md`） |
| 我观测的 | 可用，但要标观测依据与次数；攒够 `N_same` 次一致才算稳定偏好 |
| 我推断的 | **只作假设，不得当事实用于判断**；须经反馈或他确认才可升级 |

混同的代价是画像慢慢变成助理的想象，之后基于想象做判断，**而没人能发现**——与安全边界漂移同属静默失败。

## 条目标签（权重与情绪）

episodic 条目在写入时附带四个字段，由模型当场判断，用户反馈可改：

| 字段 | 含义 | 取值 |
|---|---|---|
| 效价 | 这条经历带来的情绪方向 | -1（痛苦）～ +1（愉悦） |
| 强度 | 情绪烈度 | 0 ～ 1 |
| 价值权重 | 对「我是谁」的重要性 | 0 ～ 1 |
| 关联实体 | 牵涉的人 / 事 / 物 | 自由文本 |

召回一次即强化：权重上调一档（上限 1）；长期不被召回则按「衰减与塌缩」的遗忘管线退场。偏好不靠单条事件，靠高权重模式的加权收敛。

## 经验层（记忆 → 经验）

语义结论分两种：只说「是什么」的进 semantic/；含「怎么做有效 / 无效」的，经反馈验证后提炼为**经验**，位置 `long-term/memory/experience/`：

| 字段 | 含义 |
|---|---|
| 适用场景 | 这条经验在什么条件下成立 |
| 做法 | 具体怎么做（或明确不怎么做） |
| 验证状态 | 未验证 / 已验证有效 / 被推翻 |
| 来源 | 归纳自 <episodic / semantic 指针> |
| 更新时间 | 最近一次复核时间 |

- **生成**：记忆整理时，归纳阶段若结论含做法或教训，先写经验条目并标「未验证」，不直接当可靠依据
- **验证**：反馈确认有效 → 标「已验证有效」；被新事实或用户反馈推翻 → 走「修正：只增不改」追加新条目并标「被推翻」，旧条目留演化史
- **召回**：与语义同层按需召回；未验证经验仅作参考并标注，已验证的才作为判断依据
- **边界**：经验是记忆不是规则，不自动进 `rules/` 与 `profile/`；内省时对新证据复核旧经验（见 `触发器.md`）

## 时机

每天固定「记忆整理」时刻（默认 03:00）做一次批量沉淀；用户明确反馈时立即单条处理。

## 衰减与塌缩（遗忘管线）

短期到期即清不归档。长期情景记忆按**遗忘管线**退场，判据是权重与情绪标签，时间只是参数：

```
归纳 → 降权 → 归档 → 摘索引
```

- **归纳**：条目进入遗忘期先问一句「这条里有不依赖细节、值得留下的结论或模式吗」。有则提炼——只说「是什么」的进 semantic/，含「怎么做」的走「经验层」；原条目保留形成演化史；没有则直接进入下一级。归纳不自动改动画像。
- **降权**：久未召回的低权重条目按衰减率逐档降权；高权重条目抗衰减，越重要忘得越慢。
- **归档**：权重跌破阈值后移出常规检索，不再参与少样本召回。
- **摘索引**：归档后仍久未被引用，从 `index.md` 摘除并标注，留痕可查。

召回强化与遗忘相反：被决策召回一次，权重上调一档（上限 1）。

明细不无限堆积：episodic 全文超出「可操作窗口」（默认 30 天）且未再被召回，走遗忘管线；feedback 定期收敛为结论 + 只留最近窗口原始。每次「记忆整理」先归纳、再衰减、后沉淀。

常驻记忆设低 token 预算（默认到只带语义层与近窗口，具体由配置给定）；超出部分一律靠索引按需拉，不整袋进上下文。

语义与画像不自动衰减，只在用户确认后修改；DNA 永不参与遗忘与衰减。

## 修正：只增不改

长期记忆不覆写，修正走追加：反馈写入 `feedback/`（日期、原结论、新结论、原因）→ 整理时重算 → 结果写新条目并标「替代自 <旧条目>」→ 旧条目保留形成演化史。

## 不变量

短期内容永不直接变成画像；一次异常（意外熬夜、临时换通勤）不得改写长期画像；任何自动画像改动须可回溯到具体反馈；助理不得自动改 `profile/` 与 `rules/`，只能提案由用户确认；非真实决策产生的条目（演练、联调、测试）须标注来源与性质，不得作为少样本被召回。运行时永不写 `DNA/`——DNA 只作初始化与重建依据，任何 DNA 改动只发生在离线开发流程，不由运行中的助理执行。
