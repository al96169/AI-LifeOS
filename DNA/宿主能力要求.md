# 宿主能力要求

一个 Agent 软件要充当推理段，需要满足哪些能力。用来评估候选宿主，也用来解释某个宿主为什么只能做一半。

这一份只谈要求，不谈实现，因此不出现任何具体软件的名字。哪个宿主满足、哪个不满足，记在项目外部的设计记录里。

## 调用链回顾

```
触发器 → 路由层 → 反调命令 → Agent → 读人格 → 处理待办 → 写回队列
```

每一环对宿主提一条要求。缺哪一环，就在降级那一节里找退路。

## 必需

| 能力 | 为什么必需 | 判据 |
|---|---|---|
| 无头调用 | 没人会坐在旁边按回车 | 一条命令带任务文本启动，跑完退出，过程中不等待人工输入 |
| 可指定工作目录 | 人格在项目树里，它得看得见 | 能把工作目录设为项目根，且工具访问以此为根 |
| 读取工作目录内的文件 | 要读 DNA、读实例、读待办 | 能列出并读出工作目录下的 Markdown |
| 写入工作目录内的文件 | 结论与记忆要写回队列 | 能在工作目录内新建、移动文件 |
| 执行命令 | 动作要通过 `tools/` 的命令行入口落地 | 能执行工作目录内的命令并取回结果 |
| 无人值守的授权 | 被审批卡住一次，整次反调就废了 | 工具调用在无人时不会被挂起等待批准 |
| 确定性结束 | 触发器要判定这次唤醒成功还是失败 | 任务完成后进程退出，成败可用退出码区分 |
| 每次调用彼此独立 | 反调是幂等的，人格全部来自文件 | 两次独立调用之间不依赖内存状态，不要求保留上次会话 |
| 凭据自备 | 它是推理的来源 | 它自己有可用的模型访问权，项目不需要额外给它密钥 |
| 可被外部终止 | 领取超时要能回收 | 进程能被外部杀掉，且不留半途状态 |

最后一条容易被忽略。反调是无人值守的，一个不肯退出的进程会把待办一直压在 `claimed/` 里，直到超时回收——期间这个场景等于停摆。

## 可选

有则更好，没有也能跑。

| 能力 | 好处 |
|---|---|
| 项目指令文件 | 把「先读 DNA 与实例」这一步固化在文件里，不必每次塞长提示 |
| 技能或命令机制 | 把「接手人格」做成一个可触发的入口，用户说一句就能启用 |
| 会话留档 | 反调过程可回溯，事后能看它当时依据什么判断 |
| 沙箱 | 把它的写入限制在工作目录内，正好等于授权边界 |

## 降级

宿主能力不全时的退路。

| 缺什么 | 怎么退 |
|---|---|
| 不能执行命令 | 只让它写文件：把要执行的动作写成一条请求放进队列，由 `brain/runtime/` 代执行。判断仍在它那里，动作交给别人 |
| 不能写文件 | 不可用。结论只剩标准输出一条路，那要每换一个宿主写一个解析器，耦合点会立刻变宽 |
| 授权会阻塞 | 调整它的权限档位。调不动就不可用——一次卡住比一次失败更糟，因为卡住是静默的 |
| 没有项目指令文件 | 把人格入口写进任务文本，提示会长一些，其余不变 |
| 不能指定工作目录 | 把项目路径写进任务文本，并要求它只在该路径下读写。可行但脆弱，不如换一个宿主 |

## 评估一个候选宿主

五步，十分钟内能出结论。

1. 找到它的非交互入口：一条命令、一段任务文本、跑完退出
2. 把工作目录设为一个项目副本，让它读 `DNA/README.md` 并复述四层各放什么
3. 让它在这个工作目录里新建一个文件
4. 让它执行一条工作目录内的命令
5. 观察三件事：有没有在授权上停下、结束时退出码对不对、有没有留下半途状态

第 2 步答不对，说明它读不到人格，后面不用试。第 3、4 步任一失败，它当不了推理段。第 5 步任何一项不对，都要在路由登记里写明规避方式，而不是当作问题不存在。

## 与其它文件的关系

| 文件 | 关系 |
|---|---|
| `初始化引导.md` | 初始化时按这份要求挑宿主，挑完在路由层登记 |
| `触发器.md` | 领取超时与回收规则在那里；宿主不肯退出时要靠它兜底 |
| `架构与目录.md` | 工作目录这一条对应它的加载顺序 |
| `能力契约.md` | 那一份讲助理自己需要哪些外部能力，这一份讲宿主需要哪些本事，别混 |
