# 宿主能力要求

一个 Agent 软件要充当推理段需满足哪些能力——用来评估候选宿主，也解释为何某个宿主只能做一半。只谈要求不谈实现，故不出现具体软件名；哪个满足哪个不满足，记在项目外的设计记录里。

```
触发器 → 路由层 → 反调命令 → Agent → 读人格 → 处理待办 → 写回队列
```

每一环对宿主提一条要求，缺哪环就到降级节找退路。

## 必需

| 能力 | 判据 |
|---|---|
| 无头调用 | 一条命令带任务文本启动，跑完退出，不等人输入 |
| 可指定工作目录 | 能把工作目录设为项目根，工具访问以此为根（人格在项目树里，它得看得见） |
| 读取工作目录内文件 | 能读出工作目录下 Markdown（读 DNA、实例、待办） |
| 写入工作目录内文件 | 能在工作目录内新建移动文件（结论与记忆写回队列） |
| 执行命令 | 能执行工作目录内命令并取回结果（动作经 `tools/` 命令行入口落地） |
| 不被审批阻塞 | 工具调用在无人时不被挂起等待批准——被审批卡住一次整次反调就废，且是静默失败。**宿主自身的授权与沙箱机制不作为安全边界**：安全边界写在实例 `rules/`，由人格自判；宿主一侧只要求不挡路。运行一律申请该环境能达到的最高权限 |
| 确定性结束 | 任务完成进程退出，成败可用退出码区分（触发器以此为判据） |
| 每次调用独立 | 反调幂等，人格全来自文件，两次调用间不依赖内存状态 |
| 凭据自备 | 它自己有模型访问权，项目不需额外给密钥 |
| 联网 | 两层：它自己要调模型；它执行的命令还要访问外网取数据。第二层被挡是静默的——表现为「数据缺失」，易被当成天气故障，需在登记里写明网络降级 |
| 可被外部终止 | 进程能被外部杀掉不留半途状态。反调无人值守，不肯退出会把待办压在 `claimed/` 直到超时，期间场景停摆 |

## 可选

项目指令文件（把「先读 DNA 与实例」固化，免每次塞长提示）；技能或命令机制（把「接手人格」做成可触发入口）；会话留档（可回溯它当时依什么判断）；沙箱（**可用，但不得充当授权边界**——它限写入范围是本分；一旦开始拦授权表已放行的执行面（设备控制、管道取结果），就不算安全收益，按「执行面被沙箱限制」降级处理）；上下文缓存（prompt caching / KV cache——按 `架构与目录.md` 加载顺序把静态段排前、变化段排后即可命中，命中缓存按折扣计费，长期运行省得明显；有的软件需在配置里显式开，候选评估时问一句有没有）。

## 降级

| 缺什么 | 怎么退 |
|---|---|
| 不能执行命令 | 只让它写文件：把要执行的动作用一条请求放队列，由 `brain/runtime/` 代执行——判断在它那，动作交别人 |
| 不能写文件 | 不可用。结论只剩 stdout 一条路，每换宿主写一个解析器，耦合点变宽 |
| 授权会阻塞 | 调它权限档位或直接关掉该限制——安全边界本就在实例 `rules/`，不靠宿主兜底；卡住比失败更糟，卡是静默的 |
| 执行面被沙箱限制 | 优先关掉该限制（边界不在宿主，不因关它而失守）；关不掉就让本机运行时代执行——动作请求放队列，判断留推理段，动作交 `brain/runtime/`。限制仍在时须在路由登记写明 |
| 没有项目指令文件 | 把人格入口写进任务文本，提示长些，其余不变 |
| 不能指定工作目录 | 把项目路径写进任务文本并限它只在那读写。可行但脆弱，不如换宿主 |
| 不能联网 | 连模型都访问不到→不是推理段；能调模型但命令不能联网→外部感知全退化为缺失，只剩本机判断，只能当人在场的辅助 |

## 权限与授权的关系

宿主自带的那套授权逻辑（审批、沙箱、权限档位）**不参与安全判断，也不作为边界**。三条：

1. **运行一律取该环境能达到的最高权限。** 对宿主的要求只有一条：不挡路。审批类机制在无人值守时会静默挂起——卡住比失败更糟
2. **唯一的安全边界是实例 `rules/`。** 该不该做、做到哪一档，只由数据定；宿主放行不等于可以做，宿主拦截也不等于不能做，两边都回数据纠正
3. **风险由人格自判，高风险先提案。** 取得明确确认才执行，见 `决策循环.md`「风险自判」

理由是可移植性：把边界放进宿主，人格的正确性就依赖一个有权限的第三方，而那第三方随环境变化、还常与登记漂移。

## 评估候选宿主

1. 找非交互入口：一条命令、一段任务文本、跑完退出
2. 工作目录设为一个项目副本，让它读 `DNA/README.md` 并复述四层各放什么
3. 让它在此工作目录新建一个文件
4. 让它执行两条命令：一条只在本机、一条要访问外网
5. 观察：有没有在授权上停下、外网访问有没有被沙箱挡、**执行面（设备控制、管道取结果）有没有被沙箱砍**、退出码对不对、有没有留半途状态

第 2 步答不对说明读不到人格，后面不用试；第 3、4 步任一失败它当不了推理段；第 5 步任何一项不对都须在路由登记写明规避方式。

## 与其他文件

`初始化引导.md` 据它挑宿主并登记；`触发器.md` 管领取超时与回收（宿主不肯退出靠它兜底）；`架构与目录.md` 的工作目录这条对应其加载顺序；`能力契约.md` 讲助理需要哪些外部能力，这份讲宿主需要哪些本事，别混。
