# 版本

当前版本：**1.0**

DNA 会变，落在它上面的实例不会自动跟着变。本文件管三件事：版本号怎么定、每个大版本改了什么、一个落在旧版上的实例该往哪走。改动 `DNA/` 的任何文件，都要在同一次改动里更新这里。

## 版本号怎么定

版本号表达的不是改了多少，而是**实例要不要动作**。

| 位 | 什么时候加 | 实例要做什么 |
|---|---|---|
| 主版本 | 实例不改自己的数据或定义就无法正确运行 | 必须迁移，按 `升级指导.md` 走 |
| 次版本 | 新增了可选机制，旧实例照旧能跑 | 无需动作，可择机采用 |
| 修订 | 措辞、错字、示例调整，语义不变 | 无需动作 |

同一处改动能算主版本还是次版本，取决于它对已有实例的影响，不取决于它看起来多大。改一句话而让某个场景的判定方式失效，那是主版本。

## 历史

### v1.0 — 2026-09-15

- 概要：首个版本化的状态。四层结构、决策循环、触发与派发、记忆规范、守护进程、能力契约到此定型。
- 影响文件：全部
- 实例动作：在 `config.md` 里新增「人格版本」字段并填 `1.0`。若实例建于更早状态，先按下表逐项核对，核对完即可视作落在 v1.0 上。
- 修订：全部文档纯措辞收敛，语义不变，实例无需动作。

#### 起算点之前的差异

v1.0 之前没有版本号，改动也没有留下记录。手上若有更早建立的实例，按下表核对。

| 早期状态 | 自 v1.0 起 |
|---|---|
| 目录为 `brain/`、`glue/`、`runtime/`、`logs/` | 四层：`DNA/`、`personality/`、`brain/`、`tools/` |
| 宿主相关文件由仓库预置 | 仓库不预置，初始化时由宿主自己写进 `brain/router/` |
| 触发器按阈值穿越触发，轮询间隔是一个全局值 | 触发器只报有变化、不判断要紧；感知订阅逐行给轮询间隔 |
| 场景的决策规则写成判定表 | 场景写该考虑哪些因素、按什么顺序比较 |
| 感知入口无统一约定 | 来源命令须输出 `{ok, value, freshness}`，拿不到即视为缺失 |
| 演练与真实记录混放 | 演练条目须标注来源与性质，不得被当作少样本召回 |

## 条目怎么写

每个主版本一条，四条固定内容，不要多写：

- 版本号与日期
- 概要：这一版把什么定下来了，或者改掉了什么
- 影响文件：改动落在哪几份
- 实例动作：无需动作，或要做什么；需要动手的，写清照着哪一步做

次版本与修订不单独立条，并入最近的那个主版本条目里作为补充。

## 改动 DNA 时的义务

改动 `DNA/` 的任何文件，都要在同一次改动里更新本文件：加版本号、写历史条目、写明实例要不要动作。三样缺一不可。

漏掉这一步的代价在下次升级时才显形：后来的人拿不到判断依据，只能把新旧 DNA 逐字比对，或者干脆重装一个实例，把记忆与画像一起丢掉。
