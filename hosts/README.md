# hosts（宿主接入）

外部 Agent 软件在本项目里充当推理段：它读人格、做判断、调工具。这一层存放接入它们所需的东西。

## 为什么单独一层

推理段是可替换的，这一层就是替换点。触发器与实例都不认识任何宿主软件，只认 `host.md` 里的声明。换宿主等于新增一个目录，DNA 与实例一行不动。

它既不是 DNA（不是不变量），也不是个人数据（不含画像与记忆），所以在版本库里单独成类。规则见 `../DNA/铁律.md` 的「版本库边界」。

## host.md 的字段

| 字段 | 说明 |
|---|---|
| 名称 | 宿主标识 |
| 形态 | 是命令行工具、桌面应用还是网页端 |
| 唤醒方式 | 触发器如何让它开工：命令行 / HTTP / 只能手动 |
| 唤醒命令 | 带占位符的命令模板 |
| 在线判定 | 派发前如何确认它当前可用 |
| 工具通路 | 它通过什么方式执行本项目定义的动作 |
| 人格加载 | 它读哪些文件才知道自己是谁 |
| 接线位置 | 该宿主强制要求的文件路径 |
| 领取超时 | 唤醒后多久算失败，待办回收回 `pending/` |

## 输出不走标准输出

唤醒时只给一个待办 id。宿主处理完自己把结论写回队列文件，把待办从 `claimed/` 移到 `done/`。

这样任何宿主都能当推理段，只要它会读写文件。若靠解析它的标准输出，每换一个宿主就得写一个解析器，耦合点会立刻变宽。

## 一个宿主一个目录

```
hosts/<名字>/
├─ host.md            声明：怎么唤醒、怎么判在线、怎么执行动作、领取超时
└─ target/            部署时原样复制到仓库根的内容
```

`target/` 是唯一的部署约定，不写脚本也不做链接，一条复制命令即可。宿主强制要求的文件名与目录都放在这里，项目自身的结构里不出现它们。

部署产物不入库。改适配只改 `hosts/<名字>/` 下的源，改完重跑部署。

## 不用宿主的环境

不必理会这一层。按 `../DNA/架构与目录.md` 的加载顺序直接读文件，自己实现推理段即可。项目本身不依赖任何宿主软件。

## 新增一个宿主

1. 建 `hosts/<名字>/`，写一份 `host.md`
2. 把该宿主需要的接线放进 `target/`
3. 在实例 `config.md` 里把推理提供方指向它
