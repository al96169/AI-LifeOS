# AI-LifeOS

一个专门服务某个用户、帮忙安排日常生活的 AI 助理人格，借助 Agent 平台加载和运行。它不是独立应用，也不实现某个特定 Agent 软件——它是一套定义文件加一条决策管线。交给任何能读文件、调模型、执行工具的 Agent 平台，平台就带着它跑起来，界面、对话流与模型接入都由平台提供。

它服务的是一个具体的人，而不是泛指的「用户」：这位用户的偏好、生活习惯、爱好、设备情况、性格与沟通习惯，是它做安排时的依据，见 `DNA/初始化引导.md` 与实例 `long-term/profile/`。

能力边界不在这个仓库里：能监控什么、怎么判断、往哪推送，取决于模型的本事和已申请的工具能力；仓库只提供让能力长出来的结构——定义格式、决策循环、记忆规则、触发与派发管线。行为由数据定义，代码只是特定环境的粘合剂：删掉 `brain/` 与 `tools/`，`DNA/` 与 `personality/` 仍完整可读、可在别处重建，换模型、换平台、换环境，人格原样搬走。详见 `DNA/铁律.md`。

## 四层结构

```
DNA/            项目定义，运行时只读，初始化与重建的唯一依据
personality/    人格实例，一用户一份，含记忆与密钥
brain/          运行时引擎：主循环、模型、触发器、守护进程
tools/          动作、渠道、感知、脚本
```

## 能做什么，取决于什么

| 取决于 | 具体是什么 | 看哪里 |
|---|---|---|
| 模型的本事 | 能否把定义当规则书、能否多步权衡、能否不臆造缺失 | `DNA/人格规范.md` |
| 宿主软件的本事 | 无头调用、指定工作目录、读写文件、执行命令、联网、无人值守授权 | `DNA/宿主能力要求.md` |
| 已申请的能力 | 拿得到哪些外部数据、落到哪些动作渠道 | 实例 `long-term/capabilities.md` |
| 定义完善度 | 画像记得多细、场景够不够全、规则清不清 | 实例 `skills/` `rules/` `profile/` |

四件任一提升，能安排的事就变，不封顶；换更强模型不必改定义，换能力更全的宿主只重登记。反过来说，别人写的场景对你未必适用——想做某件事，就把它写成一份 `skills/*.md`。

## 给 AI

不要先看代码，也不要先改任何东西。这一条先知道：项目不用代码定义场景，要让它会做某事就写一份 `skills/*.md` 说明要考虑哪些因素，判断每次当场做。任何知道场景名、场景阈值或「选 A 选 B」的代码都是错的，见 `DNA/初始化引导.md`。

先按顺序读（不跳）：`DNA/README.md` → `DNA/铁律.md` → `DNA/架构与目录.md` → `DNA/人格规范.md` → `DNA/版本.md` → 实例 `assistant.md` 与 `config.md` → `brain/README.md` 与 `tools/README.md`。读完用 `人格规范.md` 自检题验一遍，答不出别动手。

选择你要做的事：只想跑起来→初始化；换模型/渠道→只改 `brain/models/` 或 `tools/channels/`；改行为→改实例定义；换电脑/系统→`人格规范.md` 重建协议；实例落后→先看 `更新.md` 的检查与协商，确认后模型会告知方法，由你对实例手动逐级升。

## 初始化

从零跑起来。每步有完成标志，达不到不下走。

1. **确认环境**：能长期开机的电脑、可用运行时（语言不限）、能访问外网。运行时人格不需要 git。检查 `personality/` 下是否已有实例——有则跳到第 3 步并先比版本（落后走 `升级指导.md`，别重跑初始化会覆盖画像记忆），且第 5 步只做画像核对补缺
2. **建实例**：复制 `_template` 为 `personality/<user_id>/`，user_id 用 ASCII 小写/数字/连字符
3. **填实例**：只填 `assistant.md`（是谁）、`rules/`（打扰与授权边界）、`config.md`（阈值与本机参数）。作息暂留空、密钥不填
4. **备密钥文件**：初始化不需要任何密钥。复制 `long-term/secrets.example.env` 为 `secrets.env` 留空即可；清单各项「未申请」属正常
5. **认识用户**：主动向用户了解偏好、生活习惯、爱好、设备情况、性格与沟通方式，分几次自然对话，答案归纳进 `long-term/profile/`，作息除外（靠以后观察）。问题单与做法见 `DNA/初始化引导.md`「了解用户」。完成标志：画像初稿含这几类，且用户确认写入
6. **接通链路**：搭三件机械件——盯变化的触发器、把待办交给推理段的管线、动作落地（发消息/打电话/写提醒）。三者都不得含场景名与阈值。值班表见 `brain/README.md` 与 `tools/README.md`，接口见 `DNA/架构与目录.md`；守护进程两级锁不能省，见 `DNA/守护进程.md`。完成标志：`--status` 能列出人格、持有者、心跳
7. **接推理段**：交外部 Agent 软件（把 `DNA/初始化引导.md` 引导语交给它，它会登记进 `brain/router/`）或自己实现（按 `架构与目录.md` 加载顺序直接读文件）。接线不预置在仓库。完成标志：命令行触发一次反调，它能收到、处理、写回队列
8. **启动并校验单实例**：启动守护进程，故意再手工起一个，应被拒且日志说清是谁挡住。完成标志：第二进程取不到锁，杀持锁后重启能取得，续租失败进退让态
9. **长出一个场景**：挑一件用户真正在意的事按 `行为骨架.md` 写成 `skills/*.md`，走一遍完整链路。验证：模型按文件判断而非常识；改一阈值结论随之变；全程没动代码

初始化前先对照 `宿主能力要求.md` 挑宿主。第 6 步要注意：这条链路通常先做单实例约束，再接入推理段；顺序可按实际调整，但都不要跳到定义层。

## 日常怎么改

| 改什么 | 改哪里 |
|---|---|
| 行为倾向、阈值、调度 | 实例 `config.md` |
| 用户偏好 | 实例 `long-term/profile/`（改前确认） |
| 加场景 | 实例 `skills/` 加一份 + 补 `config.md` 与 `capabilities.md` |
| 打扰方式、授权范围 | 实例 `rules/` |
| 换模型 / 换 IM / 换外部服务 | `brain/models/` / `tools/channels/` / `tools/` 与该用户 `capabilities.md` |
| 升级新版 DNA | `DNA/版本.md` + `升级指导.md`，只改实例 |

前四行不碰代码，重启即生效。

## 版本库边界

本仓库是开发项目，只收三类：`DNA/`、`personality/_template/`、仓库骨架文件（各层 README 与占位、根 README、`LICENSE`、`.gitignore`、`.githooks`）。其余留本机：引擎代码、画像记忆、场景文件、本机配置、密钥，及宿主初始化时自写的配置与路由登记。两条守门：`.gitignore` 隐形、`.githooks/pre-commit` 拒绝越界（需 `git config core.hooksPath .githooks`）。白名单外需提交用 `--no-verify` 并写明理由。条文见 `DNA/铁律.md`。
