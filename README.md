# AI-LifeOS

一个跑在电脑里 7×24 常驻的生活助理。它融合天气、路况、日历、作息、口味与设备状态，按代价权衡动态调整安排，并在授权范围内直接执行动作——该叫醒就叫醒，该点单就点单。

规划与设计记录存放在 Obsidian 笔记库中，本仓库只放可运行的项目实体，由 Git 管理版本。

## 四层结构

```
DNA/            项目定义，运行时只读，初始化与重建的唯一依据
personality/    人格实例，一用户一份，含记忆与密钥
brain/          运行时引擎：主循环、模型、触发器、守护进程
tools/          动作、渠道、感知、脚本
```

`DNA/` 与 `personality/` 说这是什么、这是谁，`brain/` 与 `tools/` 是特定环境下的粘合剂。把后两层全部删掉，前两层仍然完整可读、可在别处重建，这是本项目的第一条约束，条文见 `DNA/铁律.md`。

## 给刚拿到这个项目的 AI

不要先看代码，也不要先改任何东西。按下面两步走。

### 第一步：建立认识

按顺序读，不要跳：

1. `DNA/README.md` — 四层各自放什么
2. `DNA/铁律.md` — 哪些事不能做。改任何东西之前都适用
3. `DNA/架构与目录.md` — 目录总览、加载顺序、接口契约、多用户规则
4. `DNA/人格规范.md` — 一个实例必须定义什么，接管与重建各按什么步骤
5. `personality/<user_id>/assistant.md` 与 `config.md` — 这个人格是谁、参数是多少
6. `brain/README.md` 与 `tools/README.md` — 引擎与工具各自负责什么

读完用 `DNA/人格规范.md` 的接管自检问题验一遍。答不出来，说明还没读懂，不要动手。

### 第二步：判断你要做的是哪件事

| 情况 | 该做的事 |
|---|---|
| 只想让它跑起来 | 进下面的「初始化」 |
| 换了模型或渠道 | 只改 `brain/models/` 或 `tools/channels/`，定义层不动 |
| 要改行为 | 改实例里的定义文件，见「日常怎么改」 |
| 换了电脑或换了机器人系统 | 按 `DNA/人格规范.md` 的重建协议走 |

## 初始化：从零到一个跑起来的助理

八步。每步末尾是完成标志，没达到就不要往下走。

### 1 确认运行环境

一台能长期开机的电脑，一个可用的运行时（语言不限），能访问外网以调用模型与天气数据。

启用提交守门，否则第二道防线不生效：

```
git config core.hooksPath .githooks
```

检查 `personality/` 下是否已有实例目录。有，说明这个环境做过初始化，跳到第 4 步。

### 2 建立实例

复制 `personality/_template/` 为 `personality/<user_id>/`。`user_id` 用 ASCII 小写字母、数字与连字符，不要用 `_template`。

完成标志：新目录下 `assistant.md`、`config.md`、`rules/`、`skills/`、`long-term/`、`short-term/` 齐全。

### 3 填实例

按 `personality/_template/README.md` 的顺序填。四项不可省：`assistant.md` 定这个人格是谁，`config.md` 定阈值与本机参数，`long-term/profile/` 定用户是谁，`rules/` 定打扰与授权边界。

完成标志：`config.md` 里不再有「待填」。

### 4 配密钥

复制 `long-term/secrets.example.env` 为 `long-term/secrets.env`，按 `long-term/capabilities.md` 的申请顺序逐项获取。密钥只写在 `secrets.env` 里，其他任何地方都不出现明文。

完成标志：清单里阶段 0 需要的四项状态为「可用」，且每项都跑通过一次真实调用。

### 5 实现引擎与工具

分工见 `brain/README.md` 与 `tools/README.md`，接口语义见 `DNA/架构与目录.md`。最小可用集合：

| 位置 | 负责 |
|---|---|
| `brain/triggers/` | 定时与事件触发，时刻取自实例 `config.md` |
| `brain/runtime/` | 主循环、上下文装配、守护进程、记忆读写 |
| `brain/models/` | 提示装配与模型调用，需支持工具调用 |
| `tools/sensors/` | 降雨曲线、通勤耗时等感知采集 |
| `tools/actions/` | 写闹钟、发消息、临界通知、外呼 |
| `tools/lib/` | 配置与密钥读取、缓存、日志、结果封装 |

守护进程按 `DNA/守护进程.md` 实现两级锁与退让逻辑，这块不能省，否则同时跑起两个实例会重复外呼。

完成标志：`--status` 能列出人格、持有者与心跳。

### 6 接上推理段

推理段可以由外部 Agent 软件承担，也可以自己实现。选前者时，把 `DNA/初始化引导.md` 的引导语交给那个软件，它会做完初始化，其中第 4 步是在 `brain/router/` 下写下自己的反调登记。密钥写进实例的 `secrets.env`。

接线不预置在仓库里：登记由 Agent 软件初始化时自己写，写在 `brain/router/`，不入库。项目不需要知道它是谁，也不需要知道它怎么存在。

不接宿主时，按 `DNA/架构与目录.md` 的加载顺序直接读文件、自己实现推理段即可。

完成标志：从命令行触发一次反调，推理段能收到、处理，并把结论写回待办队列。

### 7 首次启动并校验单实例

启动守护进程，确认只有一份在服务该人格。然后故意手工再起一个，确认它被拒绝，并且日志说清了是哪一个持有者挡住了它。

完成标志：第二个进程取不到锁；杀掉持锁进程后重启能正常取得锁；模拟续租失败时进程进入退让态并停止对外动作。

### 8 单场景验证

用 `skills/天雨通勤.md` 跑一遍完整链路：把 `config.md` 里的 `P1` 由 0.6 改成 0.8，重启服务，确认新阈值生效，期间未改动任何代码。

完成标志：改数据即改行为这一条成立。不成立就说明判断逻辑长进了代码，先搬回去。

## 日常怎么改

| 想改什么 | 改哪里 |
|---|---|
| 行为倾向、阈值、叫醒时刻 | 实例的 `config.md` |
| 用户偏好 | 实例的 `long-term/profile/`，改前需用户确认 |
| 加一个场景 | 实例的 `skills/` 加一份文件，再补 `config.md` 与 `long-term/capabilities.md` |
| 打扰方式、授权范围 | 实例的 `rules/` |
| 换模型 | `brain/models/` |
| 换 IM 渠道 | `tools/channels/` |
| 换某家外部服务 | `tools/` 与实例的 `long-term/capabilities.md` |

前四行都不碰代码，重启常驻服务即生效。

## 版本库边界

这个仓库是开发项目，只收录三类改动：`DNA/`、人格模板 `personality/_template/`、以及目录结构本身，也就是各层的 README 与占位文件。

其余全部留在本机：引擎与工具的代码、画像与记忆、场景文件、本机配置、密钥，以及各 Agent 软件初始化时为自己写入的配置与路由登记。原因与条文见 `DNA/铁律.md` 的「版本库边界」。

两道守门缺一不可。`.gitignore` 让不该出现的东西不出现在 `git status` 里，`.githooks/pre-commit` 在提交时逐条核对白名单并拒绝越界；第二道要执行一次 `git config core.hooksPath .githooks` 才生效。

确实要提交白名单外的内容，用 `git commit --no-verify`，并在提交信息里写明理由。

## 提交约定

定义文件视同代码，改动一并提交，便于回溯某次行为变化的来由。

| 前缀 | 用途 |
|---|---|
| `dna:` | 项目定义的改动 |
| `skill:` | 场景定义 |
| `rule:` | 规则 |
| `profile:` | 画像 |
| `config:` | 参数与阈值 |
| `capability:` | 能力申请与配置记录 |
| `code:` | 引擎与工具 |
| `docs:` | 说明文档 |

## 安全

实例的 `long-term/secrets.env`、运行日志、感知缓存与引擎状态不入库，锁与守护进程状态放在仓库之外的机器级运行时目录。密钥只存在于本机，仓库内只保留变量名模板。
